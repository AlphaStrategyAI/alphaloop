# alphaloop 产品设计 v0.0.1

## 0. 这份文档是什么 / 与定位的关系

这是 alphaloop 的**产品设计文档**：说明产品由哪些功能组成、这些功能怎么组织在一起、用户怎么用它们把一个大致方向变成一个经过验证的详细策略，以及最后怎么把成果交出去。

它的上游是[产品定位](./product-positioning.md)。定位回答"这个产品是给谁的、边界在哪里"；这份设计回答"于是它长成什么样"。凡是两者冲突，以定位为准：应当先修订定位，再改设计。

它**不是**定位文档，也**不是**实现方案。这里不写数据结构、不写引擎架构、不写进程与存储、不写配置文件的字段、不写命令行参数拼法。看到"这块技术上怎么做"的问题，答案不在这份文档里。

它描述的是第一版（v0.0.1）的设计范围。产品的方向性内容（例如"美、中等市场"里的"等市场"）留在定位里，不在这一版展开。

## 1. 一句话与产品亮点

**alphaloop 是一个本机优先的投资策略工坊：你随时丢进一个大致方向，它长时间自主研究，最后交给你一个经过验证的详细策略，以及一个别的项目可以直接拿去执行的策略包。**

三个关键词决定了整个设计的形状：

- **随时提交**：入口是一次对话，不是一张需要填满的表单。方向可以是粗糙的、说不清的，产品负责把它问清楚、补完整。用户不需要挑时间点、不需要凑一个"完整的想法"再来。
- **长时间自主研究**：确认开跑之后，研究自己往前走——查资料、补细节、历史模拟、验证、迭代。用户可以关掉界面去做别的事。它只在经济逻辑要改变、或数据覆盖跌破用户认下的底线时停下来等人。最长研究时间只计**有效研究时间**，不是自然时间上的一个截止时刻。
- **可靠的结论**：结论必须是可检查的。迭代过程、每一步用了哪些验证方法、验证结论是什么，都摊开给用户看；不放心的那一步可以单独重新验证一次——而且这次重验的结果算数：重验不通过，这份成果就立刻失去可实盘交接的资格。

产品亮点：

1. **一条对话就是一次研究。** 新策略 = 新对话。对话既是提交入口，也是研究过程中的工作台：看进度、处理确认、暂停、改了再跑、看结论、重验、导出，都在同一条对话里。研究途中经济逻辑改了，仍然是同一次研究、同一条对话，只是记为**新的一版**；用户不用为了改一个判断就重开一条对话、丢掉之前的上下文。
2. **确认点少而准。** 研究方法、建模方法、参数这三类小迭代自动推进，不打断人；动到经济逻辑（信号机制、目标市场、验证标准等）就停下来等确认。**改验证标准、换用的验证方法，永远算经济逻辑改动，永远要确认**，不在自动推进的范围里。用户敢把机器交出去跑很久，是因为它不会悄悄把研究变成另一件事。
3. **验证方法库会越用越厚。** 验证方法是可以预先设计、跨策略复用的资产。研究途中新加的方法会沉淀回方法库，后面的研究直接能用。用得越久，结论越可信。
4. **公开资料优先，落成本机材料。** 产品自己去取公开资料和公开市场数据，把用到的部分转成本机材料留下来复用；也可以直接使用用户已有的本机材料。取数据是研究的手段，alphaloop 不是行情终端。数据取不全时，产品只在用户开跑前认下的**最低数据覆盖容忍度**之内自动缩量继续；要跌破这条底线，必须停下来问。
5. **策略包交接是一等功能。** 研究做完，用户可以导出一个**策略包**：里面有那个经过验证的详细策略、足以检查结论是怎么来的迭代与验证记录、验证结论、以及**当时用的验证方法定义与数据来源的冻结副本**。策略包是自足的——别的项目导入它就能去做实盘执行，不需要回头依赖 alphaloop 的方法库有没有被改过。可实盘交接的策略包有明确的门槛（全部验证方法通过、没有待确认、重验依然成立）；不满足的研究导出的是另一种东西，导入方可以直接拒收。alphaloop 自己不下单、不接券商、不跑模拟盘——它的职责在"交出一个经得起检查、能被别人拿去执行的策略包"这里结束。
6. **完整交互在桌面应用里。** 同一个产品可以打包成 Mac 应用、Windows 应用或 Linux 应用。研究要人确认、或者研究结束时，桌面应用会发一条本机系统通知，所以用户可以真的走开。另外可以打包一个 CLI 应用，只做启动和看状态两件事。不是云服务。

## 2. 信息架构与功能地图

### 2.1 两种客户端

- **桌面应用（Mac / Windows / Linux）**：产品的全部界面和全部用户功能都在这里。三种平台是同一个产品在构建时打成的不同包，功能上没有差别。
- **CLI 应用**：能力是一个**封闭清单，只有两条**——启动，以及查看状态。除此之外不做任何事，也不承载任何研究功能。

### 2.2 桌面应用的信息架构

桌面应用是三个并列的主区域，加一个贯穿全局的运行状态与通知：

```
alphaloop（桌面应用）
├── 研究对话（工作台）        ← 一条对话 = 一次研究，产品的主场
│   ├── 对话区：说清方向、锁定研究设定、处理确认
│   ├── 进展区：研究现在在干什么、走到哪一步了、有效研究时间用掉多少
│   ├── 迭代与验证记录：每一版/每一轮改了什么、验了什么、结论如何
│   └── 成果区：详细策略、验证结论、重新验证、导出策略包
├── 研究列表                  ← 所有研究：草稿 / 运行中 / 等待确认 / 已暂停 / 已完成 / 已结束
├── 验证方法库                ← 预置方法 + 研究中沉淀下来的方法
└── 运行状态与通知            ← 本机是否在跑、有没有研究在等确认（常驻可见）；
                                进入等待确认、研究完成或停止时发本机系统通知
```

三个主区域的分工是清楚的：

- **研究对话**处理"这一次研究"。它是深度的、有上下文的、只服务当前这一件事。
- **研究列表**处理"我一共有哪些研究"。它是横向的、无上下文的，只负责让人找到并进入某一条对话。
- **验证方法库**处理"我用什么标准检验策略"。它跨研究存在，比任何单次研究活得更久。

### 2.3 功能地图

| 功能 | 所在位置 | 用户拿到什么 |
| --- | --- | --- |
| 新建研究、说清方向 | 研究对话 | 一个被问清楚的研究设定 |
| 确认开跑 | 研究对话 | 研究开始自主推进 |
| 看进展、看迭代与验证记录 | 研究对话 | 知道它在干什么、干过什么 |
| 处理经济逻辑确认 | 研究对话 | 研究按用户的判断继续或改向 |
| 暂停 / 改策略再跑 / 延长研究时间 | 研究对话 | 中途接管的能力 |
| 看结论、对某一步重新验证 | 研究对话 | 可检查、可复核的结论 |
| 导出策略包 | 研究对话 | 别的项目能导入执行的交接物 |
| 查找、进入、删除某一次研究 | 研究列表 | 找回或清掉任意一条研究 |
| 预先设计 / 复用 / 沉淀验证方法 | 验证方法库 | 越用越厚的验证资产 |
| 收到"要你确认了""跑完了"的提醒 | 本机系统通知 | 走开也不会错过 |
| 启动、查看状态 | CLI 应用 / 桌面应用 | 知道它活着、在跑 |

## 3. 分功能规格

### 3.1 研究对话（工作台）

**目标.** 让用户用最低成本把一个大致方向丢进来，把它谈成一个可以开跑的研究设定；开跑之后，这条对话继续作为这次研究的唯一工作台。

**入口.** 桌面应用里"新建研究"；或从研究列表点进一条已有研究。

**界面要素.**

- **对话区**：多轮对话。产品在这里追问，把方向谈成五件明确的事：
  1. **大致原理**——这个策略凭什么赚钱、信号大概从哪来。
  2. **资产类别**——在哪个市场的哪类资产上做。
  3. **最长研究时间**——最多允许它自己跑多久的**有效研究时间**。
  4. **第一轮验证方法选择**——这一次先用方法库里的哪些方法来检验。
  5. **最低数据覆盖容忍度**——数据取不全时，最少要覆盖到什么程度才算这次研究还成立：至少要有哪些资产、至少要有多长的历史区间、允许缺到什么程度。这是自动缩量的下限。
- **研究设定摘要**：以上五件事谈到什么程度，随时以摘要形式呈现在对话旁边，用户一眼能看到"它以为我要做的是什么"。这是确认开跑前的复核对象。
- **进展区**（开跑后出现）：当前在做什么（查资料 / 补细节 / 历史模拟 / 验证 / 迭代）、当前是第几版、有效研究时间用掉多少还剩多少、当前的数据覆盖离底线还有多远。
- **迭代与验证记录**（开跑后持续增长）：按版、按轮往下排。每一轮记录改了什么、为什么改、用了哪些验证方法、验证结论是什么；每一版的开头记录这一版是被什么确认开出来的。
- **确认卡片**：需要人判断时出现在对话流里（见 3.3、3.4）。
- **成果区**（有结论后出现）：详细策略、验证结论、重新验证入口、导出策略包入口，以及当前是否具备可实盘交接资格（见 3.7）。

**状态.** 一条对话对应一次研究，状态即研究状态：草稿、运行中、等待确认、已暂停、已完成、已结束（未通过 / 时间耗尽）。完整流转见 4.8。

**版本.** 一次研究内部按**版本**推进。开跑时是第一版；此后每一次经过人确认的经济逻辑改动（也包括改验证方法、改研究设定、延长最长研究时间后继续）都开出新的一版。换版不换对话、不换研究：之前所有版本的迭代与验证记录都留在同一条对话里，可以往回翻、可以前后对照。

**边界.**

- **一条对话只服务当前这一次研究。** 想做另一个策略，开新对话。但研究途中改经济逻辑**不算另一个策略**：它是同一次研究的新版本，不需要、也不应该要求用户重开一条对话。
- 它是**研究工作台，不是通用聊天窗口**。对话的目的是把研究推下去：说清方向、做判断、看结论。不承担与研究无关的问答。
- 对话不改变经济逻辑的边界：用户在对话里说的话，如果构成经济逻辑改动，走确认流程（见 3.4），不会被当作一句闲聊悄悄吸收进研究。

### 3.2 确认开跑

**目标.** 在长时间自主研究开始之前，让用户明确看到并认下"它要去研究的到底是什么、最多跑多久、拿什么标准验"。这是自主性的授权点。

**入口.** 研究对话里，五件事都谈到位之后出现的确认动作。

**界面要素.**

- 研究设定的完整摘要：大致原理、资产类别、最长研究时间、第一轮验证方法、最低数据覆盖容忍度。
- 一句关于自主边界的说明：研究方法 / 建模方法 / 参数的小迭代自动做；经济逻辑改动、以及数据覆盖要跌破你认下的底线，都会停下来问你。
- 一句关于时间的说明：最长研究时间只计有效研究时间，暂停和等你确认的时间不算。
- 确认动作；以及"再改改"的退回动作。

**状态.** 确认前，研究处于草稿。草稿会被保留下来，也出现在研究列表里，用户可以过几天回来接着谈；草稿不占用机器算力、不产生研究记录。确认后立刻进入运行中，并开出第一版。

**边界.**

- 没确认就不会开跑。产品不会"聊着就自己开始了"。
- 确认只授权这一次研究、这一套设定。研究途中要动经济逻辑、或要跌破数据覆盖底线，都需要新的确认，不能拿开跑时的确认当通行证。
- 最低数据覆盖容忍度是**授权自动缩量的边界**，不是允许悄悄缩量的免死金牌：容忍度之内自动继续并记录，容忍度之外一律停下来问。

### 3.3 研究任务（运行中的研究）

**目标.** 让研究在无人看守的情况下长时间自主推进，同时让用户任何时候回来都能看懂它在干什么、干过什么。

**入口.** 该研究的对话；或研究列表里点进去。

**界面要素.**

- **当前动作与进度**：正在做哪一步、当前第几版、这一轮是第几轮。
- **时间预算**：已用的有效研究时间与剩余额度。暂停中和等待确认中，这个数字不动，界面上明确说明"这段时间不计入"。
- **迭代与验证记录**：可以往回翻的完整历史，包含每一版的由来、每一轮的策略变化、用到的验证方法、验证结论。
- **控制动作**：暂停、（暂停后）修改策略并重新开跑、延长最长研究时间。
- **资料与数据说明**：这一次研究用到的公开资料与本机材料范围、数据取到什么时候为止、当前实际覆盖与用户认下的最低覆盖容忍度的距离。目的是让人判断结论的适用范围，不是让人来这里看行情。
- **本机系统通知**：进入等待确认时、研究完成或停止时，发一条系统通知。用户可以关掉桌面应用去做别的事，不用守着。

**状态.**

- **运行中**：自主推进，不需要人。
- **等待确认**：遇到经济逻辑改动、或数据覆盖要跌破底线，停在确认点上等人（见 3.4、4.6）。研究不再前进，但保留全部上下文，且不消耗有效研究时间。
- **已暂停**：用户主动暂停。同样不消耗有效研究时间。
- **已完成**：产出了通过验证的详细策略，具备导出可实盘交接策略包的资格（资格条件见 3.7）。
- **已结束（未通过 / 时间耗尽）**：有效研究时间用尽但没有产出通过验证的结论。

**自动推进的范围（精确定义）.** 可以不打断人自动做的，只有这三类小迭代：

- **研究方法**：换一种查资料、组织证据的做法。
- **建模方法**：在既定经济逻辑内换一种把策略写清楚、算出来的做法。
- **参数**：在既定逻辑与既定标准下调参。

**明确不在自动推进范围内**：验证标准的任何改动、这次研究所用验证方法的新增/替换/删除、以及验证方法库层面的改动。这些一律走确认（见 3.4、4.5）。"方法层面的小迭代"指的是研究和建模的方法，不包括验证方法——这两件事不能混为一谈。

**边界.**

- 经济逻辑改变一律停下来等人，不存在"先改了再告诉你"。
- 数据覆盖只能在用户认下的容忍度之内自动缩，跌破底线一律停下来等人。
- 研究不会因为用户关掉桌面应用而中断；它跑在本机上，界面只是观察和干预的窗口。

### 3.4 经济逻辑确认

**目标.** 把"这已经是另一个策略了"的时刻交回给人，并且让这个判断做起来足够快——用户不需要读完全部历史才敢点确认。

**入口.** 研究运行中自动触发，以确认卡片的形式出现在对话里；研究列表和运行状态里也能看到"有研究在等你"，同时发一条本机系统通知。

**界面要素.** 一张确认卡片说清四件事：

1. **现在打算改什么**：改动的内容，例如信号机制、目标市场、验证标准、这次研究用的验证方法这类。
2. **为什么要改**：触发这个改动的模拟或验证结果。
3. **改了之后研究会变成什么样**：与当前这一版的研究设定相比，哪里不一样了；确认之后会开出新的一版。
4. **用户的选择**：同意按这个方向继续 / 不同意（保持原经济逻辑继续找别的路）/ 暂停下来自己动手改。

**状态.** 出现确认卡片时研究处于等待确认；用户同意则开出新的一版并回到运行中，不同意则维持当前版本继续运行，选择暂停则进入已暂停。等待确认期间既不推进研究，也不消耗有效研究时间；用户不在场也不会超时自动替人决定。

**边界.**

- 确认卡片只用于经济逻辑改动和数据覆盖跌破底线这两类事。研究方法 / 建模方法 / 参数的小迭代不做成确认，否则"确认点少而准"就废了。
- 产品不替人做这个决定，也不用默认选项诱导。
- 中途新增、替换或删除验证方法属于经济逻辑改动（验证标准变了），走同一套确认流程（见 4.5）。
- 确认后的结果是**同一次研究的新版本**，不是新研究，也不要求用户开新对话。

### 3.5 验证方法库

**目标.** 让"用什么标准检验策略"成为可以沉淀、可以复用的资产，而不是每次研究临时拍脑袋。

**入口.** 桌面应用的独立区域；研究对话里选择第一轮验证方法、或中途新增方法时也会用到它。

**界面要素.**

- **方法清单**：产品预置的方法，加上历次研究中沉淀下来的方法。
- **单个方法**：它检验的是什么、适用于什么情况、由谁引入（预置 / 来自哪一次研究）。
- **管理动作**：预先新建方法、编辑方法、在开跑前为某次研究挑选方法。
- **使用情况**：这个方法被哪些研究用过。用户判断"这条标准是否可靠"时需要这个。

**状态.** 方法有两种来源：预置，或从某次研究中沉淀。研究中新增的方法一旦通过确认，就正式进入方法库，后续研究可以直接选用。

**方法定义是可追溯、不可回改的.** 编辑一个方法，得到的是这个方法的**新定义**，而不是把旧定义抹掉。研究记录和已导出的策略包引用的永远是它当时用的那份定义。含义有两条：

- 用户以后怎么改方法库，都不会让一份已有的验证结论变成另一个意思，也不会让一个已经导出的策略包失效或被悄悄改写。
- 方法库里能看出某个方法从哪一版起变成了现在这样，以及哪些研究用的是旧定义。

**边界.**

- 方法库跨研究存在，独立于任何一次研究的生死。研究结束、删除，不影响已经沉淀下来的方法。
- 在一次研究运行中新增、替换或删除方法，不是方法库里的日常编辑，而是那次研究的经济逻辑改动，必须先确认（见 4.5）。
- 方法库不是脚本仓库或插件市场，它只承载"这一版产品拿什么标准来验策略"这件事。

### 3.6 研究列表

**目标.** 让用户在多条研究之间找到自己要的那一条，尤其是"哪一条在等我确认"。

**入口.** 桌面应用的独立页面。

**界面要素.**

- 全部研究的列表，每条显示：方向的一句话概括、资产类别、状态、开始时间、最近活动时间。
- 按状态过滤：**草稿 / 运行中 / 等待确认 / 已暂停 / 已完成 / 已结束（未通过 / 时间耗尽）**。这六个状态在产品里处处一致，列表不少列任何一种。
- **草稿也在列表里**：谈了一半没开跑的研究会被保留，随时能回来接着谈，不会因为关掉窗口就没了。
- **等待确认是一等状态**：需要人处理的排在最显眼的位置，这是用户走开一段时间回来后第一眼要看到的东西。
- 点进任意一条，进入它的研究对话。
- **删除研究**：可以从列表里删掉一条研究（含草稿）。删除前明确告知后果：这条研究的对话、全部版本的迭代与验证记录一起消失，它的导出资格也随之消失，之后无法再从它导出任何策略包。已经导出到本机的策略包不受影响——它是自足的。删除不影响验证方法库里已沉淀的方法。

**边界.**

- 列表只做"找到、进入、删除"。研究本身的操作（确认、暂停、重验、导出）都在对话里做，不在列表里做。
- 不做多人视图、不做分享、不做把结果分发给别人——单人单机。

### 3.7 策略包导出（交接）

**目标.** 把一次研究的成果变成一个别的项目能**导入并用于实盘执行**的交接物。这是 alphaloop 交付链条的终点，也是它与实盘项目之间唯一的接口。

**入口.** 研究对话的成果区。这是用户主动触发的动作，不会自动导出。

**两种导出物，类型不同，不可混淆.**

- **可实盘交接的策略包**：研究通过了验证、且满足下面的资格条件时才能导出。这是给外部实盘项目导入执行的东西。
- **研究记录包**：研究没有通过验证时（例如有效研究时间用尽仍未达标）能导出的东西，内容是过程、试过的路、为什么没成。

这两者在产品语义上是**两种不同类型的产物**，不是同一种东西的两个成色。研究记录包在其身份上就带着"未通过验证、不可用于实盘执行"的标识，导入方**可以据此直接拒收**，不需要靠读文案或看人眼判断。产品不提供把研究记录包"当作"策略包使用的路径。

**可实盘交接策略包的资格条件（三条同时成立）.**

1. **当前选定的验证方法全部通过**——是"这次研究当前选定的全部方法"，不是"挑通过的那几个"。任一方法未通过，就没有资格。
2. **没有待处理的确认**——研究不处于等待确认。悬而未决的经济逻辑改动意味着这份结论还没有被认下来。
3. **重验结果依然成立**——用户对某一步重新执行过验证的，重验必须是通过的。

三条里缺任何一条，成果区就不提供可实盘交接的导出，并且直接写明缺的是哪一条、怎么补。

**重验不通过 = 立刻撤销资格.** 用户对某一步重新执行验证并且没通过时：

- 该研究**立即失去可实盘交接资格**，成果区的可实盘导出入口随即关闭。
- 界面明确说明是哪一步、哪个方法重验不通过导致的撤销。
- 已经导出到本机的旧策略包不会被追回或改写（它是自足的、当时成立的快照），但产品会在成果区标明"此前导出的策略包所依据的验证已被推翻"，让用户自己去处置下游。
- 恢复资格的唯一途径是继续研究：改了再跑、重新验证，直到三条资格条件重新同时成立。产品不提供"忽略这次重验"的开关。

**策略包必须包含（产品层面的交接契约）.** 策略包是**自足**的：导入方只靠这个包就能理解、校验并执行这个策略，不需要访问 alphaloop、不依赖用户的方法库后来有没有被改过。

1. **经过验证的详细策略本身**：信号从哪来、怎么进出、在哪个市场的哪类资产上做、用什么参数。要完整到别的项目不需要回来问就能执行。
2. **验证结论**：用这些方法验下来，结论是什么、在什么范围内成立。
3. **所用验证方法的冻结定义**：不只是方法的名字和身份，而是当时那份方法定义本身，原样冻结在包里。以后用户在方法库里怎么改这些方法，都不影响这个包里的内容和它的含义。
4. **数据出处的冻结记录**：这次研究用的是哪些公开来源与本机材料、覆盖了哪些资产与哪段历史区间、数据截止到什么时候、过程中有没有在容忍度之内缩过覆盖范围、当时认下的最低数据覆盖容忍度是什么。导入方据此判断这个策略是在什么数据条件下成立的。
5. **迭代与验证历史**：足以让人检查这个结论是怎么一步步得出来的——有过几版、每一版因为什么确认而开出、每一轮改了什么、验了什么。
6. **研究元信息**：原始方向、资产类别、有效研究时间的额度与实际耗用、研究因何结束、导出时的资格判定结果。
7. **交接声明**：这是一个研究成果，不是投资建议；alphaloop 未做任何下单、券商连接或模拟盘执行。

这里只规定策略包在产品层面**必须承载什么**，不规定它的文件格式和内部结构——那是实现的事。

**状态与规则.**

- 只有**已完成**且满足上述三条资格条件的研究，才能导出可实盘交接的策略包。
- **已结束（未通过 / 时间耗尽）**时不提供可实盘交接的策略包，只能导出研究记录包。
- **已暂停**、**等待确认**、**运行中**的研究没有可实盘交接资格；用户仍可导出研究记录包来留档。
- 导出是可重复的动作，同一次研究可以多次导出。每个导出物都记录它是在哪一版、什么时候、按什么资格判定导出的。
- 研究被删除后不能再导出任何东西；已导出到本机的包不受影响。

**边界.**

- alphaloop 不下单、不连接券商、不管账户、不跑模拟盘或实盘。导出即交接完成，之后策略去哪里、怎么执行，不是本产品的事。
- 导出界面不出现任何执行暗示：不做"一键上线""连接账户""开始交易"这类入口，也不承诺收益。
- 导出不做分发：不发给别人、不上传云端，只落在用户自己的机器上。

### 3.8 命令行应用（CLI）

**目标.** 在不打开桌面界面的情况下把 alphaloop 跑起来，并确认它还活着。

**入口.** 与桌面应用一起、在构建时打包出的 CLI 应用。

**能力：一个封闭清单，只有两条.**

- **启动**：把 alphaloop 在本机跑起来，让已有的研究继续推进。
- **查看状态**：它是否在运行、有没有研究在跑、有没有研究在等人确认。

这个清单是封闭的：没有"以及类似的检查"这种口子，就是这两条。要往 CLI 加第三条能力，得先改这份设计和定位。

**明确不做.** 用对话给出方向、确认经济逻辑改动、查看结论、重新执行验证、导出策略包、管理验证方法库、删除研究——这些一律只在桌面应用里。CLI 上不提供这些功能的替代路径。

**边界.** CLI 的存在理由是把产品跑起来并确认它活着，不是"给高级用户的另一套界面"。任何"用户要用的功能"都不往 CLI 里加；需要新功能时，加在桌面应用。

## 4. 主流程与异常流

### 4.1 主流程：从一个大致方向到一个策略包

1. **新建研究。** 用户在桌面应用里开一条新对话，说一个大致方向，可以很粗糙。
2. **多轮对话谈清设定。** 产品追问，直到大致原理、资产类别、最长研究时间、第一轮验证方法、最低数据覆盖容忍度都明确，并以摘要呈现。谈到一半可以走，草稿留在研究列表里。
3. **确认开跑。** 用户复核摘要并确认。研究进入运行中，开出第一版。
4. **自主研究。** 产品查公开资料（也用本机材料，公开资料可转成本机材料沉淀）→ 补全策略细节 → 历史数据模拟 → 用选定的验证方法验证 → 根据结果做研究方法 / 建模方法 / 参数层面的小迭代，回到补细节或模拟继续跑。用户可以离开。
5. **需要人判断时停下来。** 遇到经济逻辑改动、或数据覆盖要跌破底线，出现确认卡片并发系统通知，等用户选择后继续（见 4.4、4.6）。确认通过则开出新的一版。
6. **结束。** 两种结局，都会发系统通知：
   - **已完成**：产出通过验证的详细策略。
   - **已结束（未通过 / 时间耗尽）**：有效研究时间用尽仍未通过验证。
7. **检查结论。** 用户在成果区看详细策略、验证结论、逐版逐轮的迭代与验证记录；对不放心的某一步单独重新执行验证。
8. **导出策略包。** 满足三条资格条件的研究可以导出可实盘交接的策略包，交给别的项目去做实盘执行（见 3.7）。

### 4.2 用户主动暂停

- 用户在研究对话里暂停。研究停在当前位置，进入已暂停，已有的全部版本与记录保留。
- 已暂停的研究可以直接继续（按当前版本接着跑），或者先改策略再跑（见 4.3）。
- **暂停期间不消耗有效研究时间。** 暂停一个月再回来，剩余额度和暂停那一刻一样。

### 4.3 改策略再跑

- 前提是研究不在运行中：已暂停、等待确认、已结束（未通过 / 时间耗尽），以及已完成（例如重验不通过、想再往前做一版）都可以。用户在对话里说明要改什么——可以改经济逻辑，也可以调整资产类别、验证方法、最低数据覆盖容忍度，或延长最长研究时间。
- 产品把改动整理成新的研究设定摘要，用户确认后**开出新的一版**并重新开跑。
- 这仍然是**同一次研究、同一条对话**：之前所有版本的迭代与验证记录都不丢，记录里能看出"从第几版起，研究设定被改成了什么、是被哪一次确认改的"。
- 改动大不大，不构成"必须开新对话"的硬规则。产品最多在改动看起来已经是另一个赚钱道理时，附一句不拦路的提示：这也可以作为一条新研究重新开始。开不开新的，由用户决定；用户不理会这句提示，研究照常以新版本继续。

### 4.4 经济逻辑确认（异常流中最常见的一种）

- 触发：研究过程中判断需要改动信号机制、目标市场、验证标准这类经济逻辑。
- 研究进入等待确认，出现确认卡片并发一条本机系统通知，说清改什么、为什么、改后会变成什么样。
- 用户可以：同意继续（开出新的一版）/ 不同意（保持当前版本的经济逻辑，让它去找别的路）/ 暂停下来自己改。
- 用户不在场时，研究就停在这里等着，不自动替人选择、不超时放弃，也不消耗有效研究时间。运行状态和研究列表都会显示"有研究在等你确认"。
- 确认之后是同一次研究的下一版，不是另一次研究。

### 4.5 研究途中新增或更换验证方法

- 触发：研究到一半，发现需要一个新的检验角度，或者现有方法不适用。
- 因为这改变了验证标准，属于经济逻辑改动：研究停下来，出现确认卡片，说明要加 / 换 / 去掉什么方法、为什么、以及这会怎么影响已有的验证结论。这一类**永远不走自动推进**，哪怕改动看起来很小。
- 用户确认后：开出新的一版，新方法生效并被**沉淀进验证方法库**（作为一份新的方法定义），后续研究可以直接复用；研究带着新的验证标准继续。
- 用户不同意：研究保持原有验证标准继续，方法不入库。
- 记录上要能看出"从第几版起，验证标准变成了什么"，否则前后结论无法对照。
- 注意资格条件的连带效果：验证方法集合变了以后，"当前选定的方法全部通过"要按**新的集合**重新成立，之前的通过不自动延续（见 3.7）。

### 4.6 资料或数据拉取失败

- 表现：公开资料取不到、公开市场数据取不全或取不到。
- **在最低数据覆盖容忍度之内**：产品自己想办法——换来源、退回已沉淀的本机材料、把覆盖范围缩到还拿得到的部分，然后继续推进。这属于自动处理，不打断人，但每一次缩量都记录在案（缩了什么、为什么缩、缩完还剩多少覆盖），并显示在研究的数据说明里。
- **要跌破容忍度**：研究**必须停下来**进入等待确认，绝不自动继续。确认卡片说清缺什么、当前覆盖会掉到什么程度、与用户认下的底线差多少、这会怎么影响结论的适用范围。用户可以选择：认下更低的覆盖底线继续（这是研究设定改动，确认后开出新的一版）、提供本机材料补齐、缩小资产或时间范围重新界定这次研究（同样开新版）、或者暂停。
- 产品**永远不会**在用户不知情的情况下把覆盖缩到底线之下。这条没有例外，包括"只差一点点""缩一下就能跑完"这类情形。
- 无论哪种情况，数据的实际覆盖范围、截止时间、缩量记录都留在研究里，并进入策略包的数据出处冻结记录——结论的适用范围必须能被追溯。
- 产品不会用不完整的数据悄悄得出结论并宣称验证通过。

### 4.7 有效研究时间耗尽

- 有效研究时间用尽时，研究停止推进，进入已结束（未通过 / 时间耗尽），并发一条本机系统通知。
- 这里计的是**有效研究时间**：暂停、等待确认的那些时间都不算在内。它不是自然时间上的一个截止时刻，用户离开多久都不会"过期"。
- 用户能看到：实际跑了多少有效时间、有过几版、迭代了多少轮、试过哪些方向、最接近的结果差在哪、为什么没有通过验证。
- **没有可实盘交接的策略包。** 用户能导出的是研究记录包——一种不同类型的产物，其身份上就标明未通过验证、不可用于实盘执行，导入方可以直接拒收。
- 用户的下一步有三条，都在同一条对话里：
  1. **延长最长研究时间并继续**：追加有效研究时间额度，确认后**开出新的一版**，研究从停下的地方接着往前跑，之前所有版本的记录都保留。不需要新建研究，也不必先经过暂停状态。
  2. **改策略再跑**（见 4.3）：顺便改经济逻辑、资产范围、验证方法或覆盖底线，同样开出新的一版。
  3. **就此停下**：留着记录，或从研究列表里删掉。
- 产品不会为了给个交付物而把未通过验证的结果包装成结论，也不会自作主张地替用户延长时间。

### 4.8 状态流转

一次研究只有六个状态。下面这张表是完整的流转规则，产品里任何地方讲状态都以它为准。

| 当前状态 | 发生什么 | 去到哪 |
| --- | --- | --- |
| **草稿** | 用户还在对话里谈设定 | 停留在草稿（保留在研究列表里，随时回来接着谈） |
| **草稿** | 五项设定谈齐、用户确认开跑 | **运行中**（开出第一版） |
| **运行中** | 研究方法 / 建模方法 / 参数的小迭代 | 停留在运行中（不打断人，消耗有效研究时间） |
| **运行中** | 需要改经济逻辑（含验证标准、验证方法） | **等待确认**（发系统通知） |
| **运行中** | 数据覆盖要跌破最低容忍度 | **等待确认**（发系统通知） |
| **运行中** | 用户点暂停 | **已暂停** |
| **运行中** | 产出通过验证的详细策略 | **已完成**（发系统通知） |
| **运行中** | 有效研究时间用尽仍未通过 | **已结束（未通过 / 时间耗尽）**（发系统通知） |
| **等待确认** | 用户同意 | **运行中**（开出新的一版） |
| **等待确认** | 用户不同意 | **运行中**（维持当前版本，另找出路） |
| **等待确认** | 用户选择暂停 | **已暂停** |
| **等待确认** | 用户一直不在 | 停留在等待确认（不超时、不自动决定、不消耗有效研究时间） |
| **已暂停** | 用户继续 | **运行中**（按当前版本接着跑） |
| **已暂停** | 用户改策略后确认 | **运行中**（开出新的一版） |
| **已完成** | 用户对某一步重验且通过 | 停留在已完成（资格不变） |
| **已完成** | 用户对某一步重验且未通过 | 停留在已完成，但**立即撤销可实盘交接资格**，导出入口关闭 |
| **已完成**（含资格已撤销的） | 用户改策略 / 继续研究并确认 | **运行中**（开出新的一版）；已有记录保留，导出资格按三条条件重新判定 |
| **已结束（未通过 / 时间耗尽）** | 用户延长最长研究时间并确认 | **运行中**（开出新的一版，接着往前跑） |
| **已结束（未通过 / 时间耗尽）** | 用户改策略并确认 | **运行中**（开出新的一版） |
| **任意状态** | 用户从研究列表删除 | 研究消失，导出资格随之消失；已导出到本机的包不受影响 |

几条贯穿全表的规则：

- **只有运行中消耗有效研究时间。** 草稿、等待确认、已暂停、已完成、已结束都不消耗。
- **状态换来换去都在同一条对话里。** 换的是版本，不是研究，也不是对话。
- **只有已完成才可能具备可实盘交接资格**，而且还要同时满足 3.7 的三条条件；其余状态一律只能导出研究记录包。

## 5. 交互原则

1. **结论与证据可检查，而且检查的结果算数。** 任何结论旁边都必须能找到它的来路：第几版、哪一轮、用了哪些验证方法（哪一份定义）、验证结论是什么、数据覆盖到哪。不接受"已通过验证"这种没有出处的说法。不放心的那一步用户可以单独重验，重验不通过就立刻撤销可实盘交接资格——检查权如果不能推翻结论，就不叫检查权。

2. **确认点少而准。** 打断人是稀缺资源。研究方法、建模方法、参数的小迭代自动做完，不通知、不确认；经济逻辑改动、验证标准与验证方法的改动、数据覆盖跌破底线，一定停下来，并且一次说清"改什么、为什么、改完变成什么样"。宁可确认卡片少一点、每一张都值得读，也不要把用户训练成无脑点确认。

3. **一条对话一次研究，改主意不用换地方。** 对话是研究的容器，不是聊天记录：想做另一个策略就开新对话。但同一次研究改经济逻辑、改验证方法、延长时间，都留在原对话里，用版本记录变化。产品不会因为"这个改动有点大"就把用户赶去开新对话——上下文的连续比分类的整洁重要。

4. **可以走开。** 界面是观察和干预的窗口，不是研究的运行条件。关掉桌面应用研究照跑；要人确认或者跑完了，会有一条本机系统通知找上门。时间预算只在真正推进研究时才走，所以"走开"从来不会变成"浪费额度"。

5. **不做交易暗示。** 界面上不出现下单、连接账户、上线执行、收益承诺这类东西，也不出现"该买什么"的表达。产品交付的是策略与验证结论；执行发生在别的项目里。这条对文案、按钮、导出界面同等适用。

6. **工作台，不是通用助手。** 对话围绕把研究推下去这件事：说清方向、做判断、看结论、交接成果。它不试图成为一个什么都能聊的 AI 助手。

7. **单人单机的克制。** 不做协作、权限、分享、分发，不做云端同步，不做"团队里的其他人"。产品对界面的每一次增加都要能回答"这对一个人一台机器有什么用"。

## 6. 第一版范围 vs 非目标

### 6.1 第一版做什么

**客户端**

- 桌面应用，包含全部用户功能；在构建时可打包为 Mac 应用、Windows 应用、Linux 应用。
- 桌面应用发本机系统通知：进入等待确认时、研究完成或停止时。v1 只做这两类通知，不做更多。
- CLI 应用：启动 + 查看状态，封闭清单，仅此两条。

**功能**

- 研究对话工作台：多轮对话锁定大致原理、资产类别、最长研究时间、第一轮验证方法、最低数据覆盖容忍度；确认开跑；看进展；处理确认；暂停；改策略再跑；延长时间继续；看结论；对某一步重新执行验证；导出。
- 研究任务：长时间自主推进；研究方法 / 建模方法 / 参数的小迭代自动做；经济逻辑改动、验证标准与验证方法改动、数据覆盖跌破底线停下来等确认；有效研究时间计量（暂停与等待确认不计）。
- 版本：一次研究内部按版本推进，每次确认开出新版，全部版本留在同一条对话里。
- 验证方法库：预置方法、预先设计方法、跨研究复用、研究中新增的方法经确认后沉淀入库；方法定义可追溯、编辑产生新定义而不回改旧记录。
- 研究列表：全部研究（含草稿）的状态总览与入口，六种状态一致呈现，支持删除研究。
- 导出：可实盘交接的策略包（须满足 3.7 三条资格条件，内容自足，冻结验证方法定义与数据出处）；以及类型不同、可被导入方直接拒收的研究记录包。
- 资料与数据：产品自行获取公开资料与公开市场数据，也使用本机材料，公开资料可转为本机材料沉淀复用；容忍度之内自动缩量并记录，跌破底线必须确认。

**市场与资产（v1 实际覆盖）**

- 美国市场：股票、债券、基金。
- 中国大陆市场：股票、债券、基金。

定位里"美、中等市场"的"等市场"是产品方向，不是第一版的覆盖要求，第一版不增加其他国家的市场。

### 6.2 第一版不做（继承定位）

- **实盘执行**：不下单、不接券商、不管账户。这是另一个独立项目，通过导入策略包来对接。
- **模拟盘 / 纸面交易**：同上，不在本产品里。
- **行情终端 / 数据平台**：取数据是研究手段，不做行情浏览、看盘、选股这类界面。
- **多人协作**：不做团队、权限、共享、分发。
- **云服务**：不做托管产品、不做云端同步，本机优先。
- **投资建议**：不产出"现在该买什么"，只产出经过验证的策略。
- **把功能做进 CLI**：CLI 的能力是封闭的两条——启动、查看状态。
- **在经济逻辑改变时自作主张**：这类决定必须回到人这里。
- **在用户认下的数据覆盖底线之下继续研究**：跌破底线一定回到人这里。
- **把未通过验证的成果当成可交接结论**：研究记录包是另一种类型的产物，不能被当作策略包使用。
- **通用 AI 助手**：对话只服务于研究本身。
