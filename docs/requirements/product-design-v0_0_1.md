# alphaloop 产品设计 v0.0.1

## 0. 这份文档是什么 / 与定位的关系

这是 alphaloop 的**产品设计文档**：说明产品由哪些功能组成、这些功能怎么组织在一起、用户怎么用它们把一个大致方向变成一个经过验证的详细策略，以及最后怎么把成果交出去。

它的上游是[产品定位](./product-positioning.md)。定位回答"这个产品是给谁的、边界在哪里"；这份设计回答"于是它长成什么样"。凡是两者冲突，以定位为准：应当先修订定位，再改设计。

它**不是**定位文档，也**不是**实现方案。这里不写数据结构、不写引擎架构、不写进程与存储、不写配置文件的字段、不写命令行参数拼法。看到"这块技术上怎么做"的问题，答案不在这份文档里。

它描述的是第一版（v0.0.1）的设计范围。产品的方向性内容（例如"美、中等市场"里的"等市场"）留在定位里，不在这一版展开。

## 1. 一句话与产品亮点

**alphaloop 是一个本机优先的投资策略工坊：你随时丢进一个大致方向，它长时间自主研究，最后交给你一个经过验证的详细策略，以及一个别的项目可以直接拿去执行的策略包。**

三个关键词决定了整个设计的形状：

- **随时提交**：入口是一次对话，不是一张需要填满的表单。方向可以是粗糙的、说不清的，产品负责把它问清楚、补完整。用户不需要挑时间点、不需要凑一个"完整的想法"再来。
- **长时间自主研究**：确认开跑之后，研究自己往前走——查资料、补细节、历史模拟、验证、迭代。用户可以关掉界面去做别的事。它只在经济逻辑要改变时停下来等人。
- **可靠的结论**：结论必须是可检查的。迭代过程、每一步用了哪些验证方法、验证结论是什么，都摊开给用户看；不放心的那一步可以单独重新验证一次。

产品亮点：

1. **一条对话就是一次研究。** 新策略 = 新对话。对话既是提交入口，也是研究过程中的工作台：看进度、处理确认、暂停、改了再跑、看结论、重验、导出，都在同一条对话里。不用在页面之间找自己的研究进行到哪了。
2. **确认点少而准。** 方法和参数层面的小迭代自动推进，不打断人；只有经济逻辑改变（信号机制、目标市场、验证标准等）才停下来等确认。用户敢把机器交出去跑很久，是因为它不会悄悄把研究变成另一件事。
3. **验证方法库会越用越厚。** 验证方法是可以预先设计、跨策略复用的资产。研究途中新加的方法会沉淀回方法库，后面的研究直接能用。用得越久，结论越可信。
4. **公开资料优先，落成本机材料。** 产品自己去取公开资料和公开市场数据，把用到的部分转成本机材料留下来复用；也可以直接使用用户已有的本机材料。取数据是研究的手段，alphaloop 不是行情终端。
5. **策略包交接是一等功能。** 研究做完，用户可以导出一个**策略包**：里面有那个经过验证的详细策略、足以检查结论是怎么来的迭代与验证记录、验证结论、以及用到的验证方法的身份。别的项目导入这个策略包就能去做实盘执行。alphaloop 自己不下单、不接券商、不跑模拟盘——它的职责在"交出一个经得起检查、能被别人拿去执行的策略包"这里结束。
6. **完整交互在桌面应用里。** 同一个产品可以打包成 Mac 应用、Windows 应用或 Linux 应用。另外可以打包一个 CLI 应用，只做启动和看运行状态。不是云服务。

## 2. 信息架构与功能地图

### 2.1 两种客户端

- **桌面应用（Mac / Windows / Linux）**：产品的全部界面和全部用户功能都在这里。三种平台是同一个产品在构建时打成的不同包，功能上没有差别。
- **CLI 应用**：只做两件事——把 alphaloop 启动起来，以及查看它现在的运行状态（例如是否在跑、有没有研究正在进行、有没有研究在等人确认）。它不承载任何研究功能。

### 2.2 桌面应用的信息架构

桌面应用是三个并列的主区域，加一个贯穿全局的运行状态指示：

```
alphaloop（桌面应用）
├── 研究对话（工作台）        ← 一条对话 = 一次研究，产品的主场
│   ├── 对话区：说清方向、锁定研究设定、处理确认
│   ├── 进展区：研究现在在干什么、走到哪一步了
│   ├── 迭代与验证记录：每一轮改了什么、验了什么、结论如何
│   └── 成果区：详细策略、验证结论、重新验证、导出策略包
├── 研究列表                  ← 所有研究：进行中 / 已暂停 / 已完成 / 已结束
├── 验证方法库                ← 预置方法 + 研究中沉淀下来的方法
└── 运行状态                  ← 本机是否在跑、是否有研究在等确认（轻量，常驻可见）
```

三个主区域的分工是清楚的：

- **研究对话**处理"这一次研究"。它是深度的、有上下文的、只服务当前这一件事。
- **研究列表**处理"我一共有哪些研究"。它是横向的、无上下文的，只负责让人找到并进入某一条对话。
- **验证方法库**处理"我用什么标准检验策略"。它跨研究存在，比任何单次研究活得更久。

### 2.3 功能地图

| 功能 | 所在位置 | 用户拿到什么 |
| --- | --- | --- |
| 新建研究、说清方向 | 研究对话 | 一个被问清楚的研究设定 |
| 确认开跑 | 研究对话 | 研究开始自主推进 |
| 看进展、看迭代与验证记录 | 研究对话 | 知道它在干什么、干过什么 |
| 处理经济逻辑确认 | 研究对话 | 研究按用户的判断继续或改向 |
| 暂停 / 改策略再跑 | 研究对话 | 中途接管的能力 |
| 看结论、对某一步重新验证 | 研究对话 | 可检查、可复核的结论 |
| 导出策略包 | 研究对话 | 别的项目能导入执行的交接物 |
| 查找、进入某一次研究 | 研究列表 | 找回任意一条研究 |
| 预先设计 / 复用 / 沉淀验证方法 | 验证方法库 | 越用越厚的验证资产 |
| 启动、查看运行状态 | CLI 应用 / 桌面应用 | 知道它活着、在跑 |

## 3. 分功能规格

### 3.1 研究对话（工作台）

**目标.** 让用户用最低成本把一个大致方向丢进来，把它谈成一个可以开跑的研究设定；开跑之后，这条对话继续作为这次研究的唯一工作台。

**入口.** 桌面应用里"新建研究"；或从研究列表点进一条已有研究。

**界面要素.**

- **对话区**：多轮对话。产品在这里追问，把方向谈成四件明确的事：
  1. **大致原理**——这个策略凭什么赚钱、信号大概从哪来。
  2. **资产类别**——在哪个市场的哪类资产上做。
  3. **最长研究时间**——最多允许它自己跑多久。
  4. **第一轮验证方法选择**——这一次先用方法库里的哪些方法来检验。
- **研究设定摘要**：以上四件事谈到什么程度，随时以摘要形式呈现在对话旁边，用户一眼能看到"它以为我要做的是什么"。这是确认开跑前的复核对象。
- **进展区**（开跑后出现）：当前在做什么（查资料 / 补细节 / 历史模拟 / 验证 / 迭代）、已经跑了多久、还剩多少研究时间。
- **迭代与验证记录**（开跑后持续增长）：一轮一轮往下排。每一轮记录改了什么、为什么改、用了哪些验证方法、验证结论是什么。
- **确认卡片**：需要人判断时出现在对话流里（见 3.3、3.4）。
- **成果区**（有结论后出现）：详细策略、验证结论、重新验证入口、导出策略包入口。

**状态.** 一条对话对应一次研究，状态即研究状态：草稿（还没开跑）、进行中、等待确认、已暂停、已完成、已结束（时间耗尽）。

**边界.**

- **一条对话只服务当前这一次研究。** 想做另一个策略，开新对话；不在旧对话里换方向。
- 它是**研究工作台，不是通用聊天窗口**。对话的目的是把研究推下去：说清方向、做判断、看结论。不承担与研究无关的问答。
- 对话不改变经济逻辑的边界：用户在对话里说的话，如果构成经济逻辑改动，走确认流程（见 3.4），不会被当作一句闲聊悄悄吸收进研究。

### 3.2 确认开跑

**目标.** 在长时间自主研究开始之前，让用户明确看到并认下"它要去研究的到底是什么、最多跑多久、拿什么标准验"。这是自主性的授权点。

**入口.** 研究对话里，四件事都谈到位之后出现的确认动作。

**界面要素.**

- 研究设定的完整摘要：大致原理、资产类别、最长研究时间、第一轮验证方法。
- 一句关于自主边界的说明：小迭代自动做，经济逻辑改动会停下来问你。
- 确认动作；以及"再改改"的退回动作。

**状态.** 确认前，研究处于草稿，不占用机器、不产生记录。确认后立刻进入进行中。

**边界.**

- 没确认就不会开跑。产品不会"聊着就自己开始了"。
- 确认只授权这一次研究、这一套设定。研究途中要动经济逻辑，需要新的确认，不能拿开跑时的确认当通行证。

### 3.3 研究任务（进行中的研究）

**目标.** 让研究在无人看守的情况下长时间自主推进，同时让用户任何时候回来都能看懂它在干什么、干过什么。

**入口.** 该研究的对话；或研究列表里点进去。

**界面要素.**

- **当前动作与进度**：正在做哪一步、这一轮是第几轮。
- **时间预算**：已用时间与剩余的最长研究时间。
- **迭代与验证记录**：可以往回翻的完整历史，包含每一轮的策略变化、用到的验证方法、验证结论。
- **控制动作**：暂停、（暂停后）修改策略并重新开跑。
- **资料与数据说明**：这一次研究用到的公开资料与本机材料范围，以及数据取到什么时候为止。目的是让人判断结论的适用范围，不是让人来这里看行情。

**状态.**

- **进行中**：自主推进，不需要人。
- **等待确认**：遇到经济逻辑改动，停在确认点上等人（见 3.4）。研究不再前进，但保留全部上下文。
- **已暂停**：用户主动暂停。
- **已完成**：产出了通过验证的详细策略，可以导出可交接的策略包。
- **已结束（时间耗尽）**：到达最长研究时间但没有产出通过验证的结论。

**边界.**

- 自动推进的范围只有方法层面和参数层面的小迭代。
- 经济逻辑改变一律停下来等人，不存在"先改了再告诉你"。
- 研究不会因为用户关掉桌面应用而中断；它跑在本机上，界面只是观察和干预的窗口。

### 3.4 经济逻辑确认

**目标.** 把"这已经是另一个策略了"的时刻交回给人，并且让这个判断做起来足够快——用户不需要读完全部历史才敢点确认。

**入口.** 研究进行中自动触发，以确认卡片的形式出现在对话里；研究列表和运行状态里也能看到"有研究在等你"。

**界面要素.** 一张确认卡片说清四件事：

1. **现在打算改什么**：改动的内容，例如信号机制、目标市场、验证标准这类。
2. **为什么要改**：触发这个改动的模拟或验证结果。
3. **改了之后研究会变成什么样**：与原本的研究设定相比，哪里不一样了。
4. **用户的选择**：同意按这个方向继续 / 不同意（保持原经济逻辑继续找别的路）/ 暂停下来自己动手改。

**状态.** 出现确认卡片时研究处于等待确认；用户做出选择后回到进行中或已暂停。等待确认期间不消耗研究进度，用户不在场也不会超时自动替人决定。

**边界.**

- 确认卡片只用于经济逻辑改动。小迭代不做成确认，否则"确认点少而准"就废了。
- 产品不替人做这个决定，也不用默认选项诱导。
- 中途新增或更换验证方法属于经济逻辑改动（验证标准变了），走同一套确认流程（见 4.5）。

### 3.5 验证方法库

**目标.** 让"用什么标准检验策略"成为可以沉淀、可以复用的资产，而不是每次研究临时拍脑袋。

**入口.** 桌面应用的独立区域；研究对话里选择第一轮验证方法、或中途新增方法时也会用到它。

**界面要素.**

- **方法清单**：产品预置的方法，加上历次研究中沉淀下来的方法。
- **单个方法**：它检验的是什么、适用于什么情况、由谁引入（预置 / 来自哪一次研究）。
- **管理动作**：预先新建方法、编辑方法、在开跑前为某次研究挑选方法。
- **使用情况**：这个方法被哪些研究用过。用户判断"这条标准是否可靠"时需要这个。

**状态.** 方法有两种来源：预置，或从某次研究中沉淀。研究中新增的方法一旦通过确认，就正式进入方法库，后续研究可以直接选用。

**边界.**

- 方法库跨研究存在，独立于任何一次研究的生死。研究结束、删除，不影响已经沉淀下来的方法。
- 在一次研究进行中新增或更换方法，不是方法库里的日常编辑，而是那次研究的经济逻辑改动，必须先确认（见 4.5）。
- 方法库不是脚本仓库或插件市场，它只承载"这一版产品拿什么标准来验策略"这件事。

### 3.6 研究列表

**目标.** 让用户在多条研究之间找到自己要的那一条，尤其是"哪一条在等我确认"。

**入口.** 桌面应用的独立页面。

**界面要素.**

- 全部研究的列表，每条显示：方向的一句话概括、资产类别、状态、开始时间、最近活动时间。
- 按状态过滤：进行中 / 等待确认 / 已暂停 / 已完成 / 已结束（时间耗尽）。
- 需要人处理的（等待确认）排在显眼位置。
- 点进任意一条，进入它的研究对话。

**边界.**

- 列表只做"找到并进入"。研究本身的操作（确认、暂停、重验、导出）都在对话里做，不在列表里做。
- 不做多人视图、不做分享、不做把结果分发给别人——单人单机。

### 3.7 策略包导出（交接）

**目标.** 把一次研究的成果变成一个别的项目能**导入并用于实盘执行**的交接物。这是 alphaloop 交付链条的终点，也是它与实盘项目之间唯一的接口。

**入口.** 研究对话的成果区，在研究产出通过验证的详细策略之后。这是用户主动触发的动作，不会自动导出。

**策略包必须包含（产品层面的交接契约）.**

1. **经过验证的详细策略本身**：信号从哪来、怎么进出、在哪个市场的哪类资产上做、用什么参数。要完整到别的项目不需要回来问就能执行。
2. **验证结论**：用这些方法验下来，结论是什么、在什么范围内成立。
3. **所用验证方法的身份**：每条结论是用方法库里的哪些方法得出的，可被指名追溯。不是只给一句"已通过验证"。
4. **迭代与验证历史**：足以让人检查这个结论是怎么一步步得出来的——每一轮改了什么、为什么改、验了什么。
5. **研究元信息**：原始方向、资产类别、研究起止与耗时、资料与数据的覆盖范围和截止时间、研究因何结束。
6. **交接声明**：这是一个研究成果，不是投资建议；alphaloop 未做任何下单、券商连接或模拟盘执行。

这里只规定策略包在产品层面**必须承载什么**，不规定它的文件格式和内部结构——那是实现的事。

**状态与规则.**

- 只有**已完成**（产出了通过验证的详细策略）的研究，才能导出可交接、可用于实盘执行的策略包。
- **已结束（时间耗尽）**且没有通过验证的结论时，**不提供可用于实盘执行的策略包**。这种情况下用户能导出的只是研究记录（过程、试过的路、为什么没成），并且导出物会明确标注为"未通过验证，不可用于实盘执行"。
- **已暂停**、**等待确认**中的研究同上：没有通过验证的结论就没有可执行的策略包。
- 导出是可重复的动作。同一次研究可以多次导出。

**边界.**

- alphaloop 不下单、不连接券商、不管账户、不跑模拟盘或实盘。导出即交接完成，之后策略去哪里、怎么执行，不是本产品的事。
- 导出界面不出现任何执行暗示：不做"一键上线""连接账户""开始交易"这类入口，也不承诺收益。
- 导出不做分发：不发给别人、不上传云端，只落在用户自己的机器上。

### 3.8 命令行应用（CLI）

**目标.** 在不打开桌面界面的情况下把 alphaloop 跑起来，并确认它还活着。

**入口.** 与桌面应用一起、在构建时打包出的 CLI 应用。

**能力.**

- **启动**：把 alphaloop 在本机跑起来，让已有的研究继续推进。
- **查看运行状态**：它是否在运行、有没有研究正在进行、有没有研究在等人确认，以及类似的运维性检查。

**明确不做.** 用对话给出方向、确认经济逻辑改动、查看结论、重新执行验证、导出策略包——这些一律只在桌面应用里。CLI 上不提供这些功能的替代路径。

**边界.** CLI 的存在理由是运维，不是"给高级用户的另一套界面"。任何"用户要用的功能"都不往 CLI 里加；需要新功能时，加在桌面应用。

## 4. 主流程与异常流

### 4.1 主流程：从一个大致方向到一个策略包

1. **新建研究。** 用户在桌面应用里开一条新对话，说一个大致方向，可以很粗糙。
2. **多轮对话谈清设定。** 产品追问，直到大致原理、资产类别、最长研究时间、第一轮验证方法都明确，并以摘要呈现。
3. **确认开跑。** 用户复核摘要并确认。研究进入进行中。
4. **自主研究。** 产品查公开资料（也用本机材料，公开资料可转成本机材料沉淀）→ 补全策略细节 → 历史数据模拟 → 用选定的验证方法验证 → 根据结果做方法/参数层面的小迭代，回到补细节或模拟继续跑。用户可以离开。
5. **需要人判断时停下来。** 遇到经济逻辑改动，出现确认卡片，等用户选择后继续（见 4.4）。
6. **结束。** 两种结局：
   - **已完成**：产出通过验证的详细策略。
   - **已结束（时间耗尽）**：到达最长研究时间仍未通过验证。
7. **检查结论。** 用户在成果区看详细策略、验证结论、迭代与验证记录；对不放心的某一步单独重新执行验证。
8. **导出策略包。** 已完成的研究可以导出可交接的策略包，交给别的项目去做实盘执行。

### 4.2 用户主动暂停

- 用户在研究对话里暂停。研究停在当前位置，进入已暂停，已有的迭代与验证记录全部保留。
- 已暂停的研究可以直接继续（按原设定接着跑），或者先改策略再跑（见 4.3）。
- 暂停不消耗研究时间预算。

### 4.3 改策略再跑

- 前提是研究处于已暂停或等待确认。用户在对话里说明要改什么——可以改经济逻辑，也可以调整资产类别、最长研究时间或验证方法。
- 产品把改动整理成新的研究设定摘要，用户确认后重新开跑。
- 这仍然是**同一次研究、同一条对话**：改动前的迭代与验证记录不丢，记录里能看出"从这里开始，研究设定被改成了什么"。
- 如果改动实际上换了一个赚钱的道理、换成了另一个策略，产品会指出这更适合开一条新对话——一条对话一次研究。

### 4.4 经济逻辑确认（异常流中最常见的一种）

- 触发：研究过程中判断需要改动信号机制、目标市场、验证标准这类经济逻辑。
- 研究进入等待确认，出现确认卡片，说清改什么、为什么、改后会变成什么样。
- 用户可以：同意继续 / 不同意（保持原经济逻辑，让它去找别的路）/ 暂停下来自己改。
- 用户不在场时，研究就停在这里等着，不自动替人选择、不超时放弃。运行状态和研究列表都会显示"有研究在等你确认"。

### 4.5 研究途中新增或更换验证方法

- 触发：研究到一半，发现需要一个新的检验角度，或者现有方法不适用。
- 因为这改变了验证标准，属于经济逻辑改动：研究停下来，出现确认卡片，说明要加/换什么方法、为什么、以及这会怎么影响已有的验证结论。
- 用户确认后：新方法生效并被**沉淀进验证方法库**，后续研究可以直接复用；研究带着新的验证标准继续。
- 用户不同意：研究保持原有验证标准继续，方法不入库。
- 记录上要能看出"从哪一轮起，验证标准变了"，否则前后结论无法对照。

### 4.6 资料或数据拉取失败

- 表现：公开资料取不到、公开市场数据取不全或取不到。
- 产品先自己想办法：换来源、退回已沉淀的本机材料、缩小到还能覆盖的数据范围继续推进。这属于自动处理的范围，不打断人。
- 如果缺的数据让研究**没法按既定设定继续**（例如目标资产的历史数据根本拿不到），研究停下来告诉用户缺什么、影响了什么，让用户选择：缩小资产范围或时间范围（这构成研究设定改动，走确认）、提供本机材料、或者暂停。
- 无论哪种情况，数据的实际覆盖范围与截止时间都记录在研究里，并进入策略包的研究元信息——结论的适用范围必须能被追溯。
- 产品不会用不完整的数据悄悄得出结论并宣称验证通过。

### 4.7 最长研究时间耗尽

- 到达用户设定的最长研究时间时，研究停止推进，进入已结束（时间耗尽）。
- 用户能看到：跑了多久、迭代了多少轮、试过哪些方向、最接近的结果差在哪、为什么没有通过验证。
- **没有可用于实盘执行的策略包。** 用户可以导出研究记录，但它被明确标注为未通过验证、不可用于实盘执行。
- 用户的下一步：延长最长研究时间接着跑、改策略再跑（见 4.3），或者就此停在这里。产品不会为了给个交付物而把未通过验证的结果包装成结论。

## 5. 交互原则

1. **结论与证据可检查。** 任何结论旁边都必须能找到它的来路：哪一轮、用了哪些验证方法、验证结论是什么、数据覆盖到哪。不接受"已通过验证"这种没有出处的说法。不放心的那一步，用户可以单独重新验证一次。

2. **确认点少而准。** 打断人是稀缺资源。方法与参数的小迭代自动做完，不通知、不确认；经济逻辑改动一定停下来，并且一次说清"改什么、为什么、改完变成什么样"。宁可确认卡片少一点、每一张都值得读，也不要把用户训练成无脑点确认。

3. **一条对话一次研究。** 对话是研究的容器，不是聊天记录。想做另一个策略就开新对话；同一条对话里只推进当前这一次研究。这样任何时候回到一条对话，上下文都是完整且唯一的。

4. **可以走开。** 界面是观察和干预的窗口，不是研究的运行条件。关掉桌面应用研究照跑；回来时不需要"补看"，进展区和记录会告诉用户这段时间发生了什么、有没有事情在等他。

5. **不做交易暗示。** 界面上不出现下单、连接账户、上线执行、收益承诺这类东西，也不出现"该买什么"的表达。产品交付的是策略与验证结论；执行发生在别的项目里。这条对文案、按钮、导出界面同等适用。

6. **工作台，不是通用助手。** 对话围绕把研究推下去这件事：说清方向、做判断、看结论、交接成果。它不试图成为一个什么都能聊的 AI 助手。

7. **单人单机的克制。** 不做协作、权限、分享、分发，不做云端同步，不做"团队里的其他人"。产品对界面的每一次增加都要能回答"这对一个人一台机器有什么用"。

## 6. 第一版范围 vs 非目标

### 6.1 第一版做什么

**客户端**

- 桌面应用，包含全部用户功能；在构建时可打包为 Mac 应用、Windows 应用、Linux 应用。
- CLI 应用：启动 + 查看运行状态。

**功能**

- 研究对话工作台：多轮对话锁定大致原理、资产类别、最长研究时间、第一轮验证方法；确认开跑；看进展；处理经济逻辑确认；暂停；改策略再跑；看结论；对某一步重新执行验证；导出策略包。
- 研究任务：长时间自主推进，方法/参数小迭代自动做，经济逻辑改动停下来等确认。
- 验证方法库：预置方法、预先设计方法、跨研究复用、研究中新增的方法经确认后沉淀入库。
- 研究列表：全部研究的状态总览与入口。
- 策略包导出：面向外部实盘执行项目的交接物，内容按 3.7 的交接契约。
- 资料与数据：产品自行获取公开资料与公开市场数据，也使用本机材料，公开资料可转为本机材料沉淀复用。

**市场与资产（v1 实际覆盖）**

- 美国市场：股票、债券、基金。
- A 股（中国）市场：股票、债券、基金。

定位里"美、中等市场"的"等市场"是产品方向，不是第一版的覆盖要求，第一版不增加其他国家的市场。

### 6.2 第一版不做（继承定位）

- **实盘执行**：不下单、不接券商、不管账户。这是另一个独立项目，通过导入策略包来对接。
- **模拟盘 / 纸面交易**：同上，不在本产品里。
- **行情终端 / 数据平台**：取数据是研究手段，不做行情浏览、看盘、选股这类界面。
- **多人协作**：不做团队、权限、共享、分发。
- **云服务**：不做托管产品、不做云端同步，本机优先。
- **投资建议**：不产出"现在该买什么"，只产出经过验证的策略。
- **把功能做进 CLI**：CLI 只做启动与运行状态这类运维性检查。
- **在经济逻辑改变时自作主张**：这类决定必须回到人这里。
- **通用 AI 助手**：对话只服务于研究本身。
