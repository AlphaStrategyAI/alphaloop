## 0. 这份文档是什么 / 与上游的关系

这是 alphaloop 的**设置功能**规格。设置里有三部分：数据源、大模型、界面语言。数据源和大模型共用第 1 节的密钥安全和测试连接。界面语言见第 4 节。

上游是[产品定位](./product-positioning.md)和[产品设计 v0.0.1](./product-design-v0_0_1.md)。哪一族需要哪类数据，对照[策略族 v1](./strategy-families-v1.md)。定位优先。本文不改六种研究状态、五条交接资格和「不下单」。五条是原来的四条，加上导出时的 `coverage_satisfied`。

**与 V1 交付收口的关系。** [V1 交付收口](./v1-cut-line.md) 锁的是已经交出去的第一版。本地导入原写在 P1，现与五个策略族一起提前到 M2。与收口不一致时，M2 及以后以本文和策略族规格为准；已经交出去的 V1 路径不因此改写。

本文不是实现方案。不写密钥的加密算法、不写数据库表、不写某个供应商 SDK 的函数名，也不写各家大模型的请求字段。

## 1. 共用规则：密钥安全与测试连接

数据源的密钥、大模型的 api key，以及任何能代替它们的刷新材料，都适用本节。

**存放。** 首选系统钥匙串（macOS Keychain、Windows Credential Manager、Linux Secret Service）。用户换电脑时，产品不把它们同步到云上。本机优先，没有云端钥匙串。没有 Secret Service（没有 gnome-keyring 或 KWallet）时，让用户在「仅本次会话」和「口令加密的本机文件」里选。仅本次会话的材料退出即失。口令加密的文件每次启动由用户输入口令。绝不静默存成明文。

**不得出现在：**

- 研究对话、确认卡、结论页
- 迭代与验证记录
- 策略包和研究记录包
- 日志、错误信息和测试连接的失败说明
- 导出的文件名

研究记录可以写数据源的账户别名、大模型的模型名，以及接入地址的主机名（含端口，不含路径里的密钥、不含查询参数）。确认卡和策略包只出现别名、源的名称和拉取时间。

**测试连接。** 设置页上的测试不把密钥发到研究记录里。成功和失败都用白话。

- 成功：说明这一项现在可用，并给出第 2 节或第 3 节要求的那几项结果。
- 失败：说明人能看懂的原因，例如地址没有响应、密钥被拒绝、模型名不存在、历史长度不够。原因里不出现完整密钥，也不出现地址上的查询参数。

失败不自动改试另一个已配置的账户或模型。

## 2. 数据源

### 2.1 原则

研究数据是用户自己的。除 Yahoo（美股）与 AkShare（A 股）两个未经许可的来源外，不内置行情源。这两个来源不是默认选中。M2 期间不下线；是否下线、何时下线，在 M2 出口评审时再议。规则见第 2.6 节。M2 不购买数据商账户，五家商业数据商一律显示「尚未对接」。

用户配置的是**自己的账户**：有账户的数据商、免费但要表明身份的官方来源、或者自己的文件。确认使用之前，用户要明确写下：我有权把这份数据用于这次研究。产品把这句话记进研究，不代替用户去向数据商保证。

数据血缘一旦进了某一版研究，就不再悄悄换成另一家。换源、换代理证券，都开新版。

### 2.2 数据类别

产品只认下面五类。一个源可以覆盖其中几类，确认卡按类写，不按「这家什么都有」写。

| 类别 | 研究要用它做什么 | 不算数的情况 |
| --- | --- | --- |
| 行情与总回报 | 价格路径、波动、反转、再平衡后的收益 | 只有不复权价或价格指数，分红和票息被当成零 |
| 财报及发布日 | 基本面信号，以及发布时点 | 只有报告期、没有公开时点；修订回填到发布前 |
| 指数成分 | 按某个指数定义标的池，并知道何时加入、何时退出 | 只有今天的成分名单，却拿去回看更早的历史还不警示 |
| 行业分类 | 行业中性，或按行业过滤 | 没有时点，用今天的行业贴到历史持仓上还不警示 |
| 价差与成本 | 核对或替换产品已定的成本假设 | 把未知价差写成已经测过的全市场统计 |

成本数字本身有一部分不依赖数据商。[策略族 v1](./strategy-families-v1.md)已定：美市主流 ETF 单边 1 bp，美股个股单边 5 bp。个股 5 bp 是保守产品假设。没有价差数据源也可以开跑，结论页仍要标注这个假设。价差源是可选的。

### 2.3 每个策略族需要哪几类

「必须」是没有它就不能开跑这一族。「可选」缺了不挡住开跑，用了就要进血缘。

| 族 | 行情与总回报 | 财报及发布日 | 指数成分 | 行业分类 | 价差与成本 |
| --- | --- | --- | --- | --- | --- |
| 低波 | 必须。个股总回报 | 不需要 | 池子若定义为指数，必须有时点成分；用户给出固定名单时改为可选，并用名单就要警示幸存者偏差 | 可选 | 成本假设必须使用已定的个股 5 bp。价差源可选 |
| 股债再平衡 | 必须。已定代理 SPY 与 AGG 的总回报；若这一版改用 IEF，则是 SPY 与 IEF | 不需要 | 不需要 | 不需要 | ETF 单边 1 bp 必须使用。价差源可选 |
| 均值回归 | 必须。个股总回报 | 不需要 | 与低波相同 | 可选 | 与低波相同，另加 0/5/10/20 bp 敏感性 |
| 基本面因子 | 必须。个股总回报 | 必须。发布时点不晚于信号日 | 与低波相同 | 行业中性关闭时不需要；用户确认打开后必须有时点行业 | 与低波相同 |
| 全天候 | 必须。SPY、TLT、IEF、GLD、DBC 五只的总回报，共同起点不早于 2006-02-03 | 不需要 | 不需要 | 不需要 | ETF 单边 1 bp 必须使用。价差源可选 |

缺了「必须」的那一类，新建研究不能确认开跑，设置里引导用户去补这个源。不得用另一类数据顶上，也不得改跑另一个族。

### 2.4 三种源

**有账户的 API 数据商.** 许可责任在用户和数据商之间。第 2.5 节的五家在 M2 一律显示「尚未对接」：不存密钥、不测试连接、不绑定到研究。不要显示成已经连上，也不要提供密钥框。M2 之后若对接某一家，再按那一家的账户形态配置密钥、测试连接和类别。

**免费的官方来源.** SEC EDGAR 是这一类的已核对例子。它不发商业 API 密钥。用户要配置的是 **User-Agent 里的联系邮箱**，并确认自己会遵守公平访问：当前上限每秒 10 次请求。产品按这个身份去取提交记录和 XBRL，不把邮箱写成密钥，但也不把别人的邮箱拿来用。

EDGAR 能覆盖的是美国财报及发布日，以及公司当前的 SIC。它不提供总回报价格，也不提供时点化的指数成分。发布时点的用法沿用策略族规格：优先用 acceptanceDateTime；只有日期时，信号不早于下一交易日。companyfacts 会不会覆盖旧值，仍待定。待定未解开时，做不到保留旧值就判 PIT 不通过。

其他免费官方源未逐家核对的，不写进「已经可对接」清单。

**用户导入的本地文件.** M2 只导入 CSV。用户选择本机的 CSV，并宣告口径。产品不猜测文件是不是总回报。Parquet 放到 M2 之后，M2 不提供 Parquet 入口。

行情文件至少要有：日期、证券代码、收盘或净值水平、币种，以及一条口径宣告。口径只有两种可选：

- **总回报**：分红或票息已经再投资在这个水平里。
- **价格**：不含分红和票息。

宣告为价格的文件，不能满足任何要求总回报的族。用户改口说「其实是总回报」而不改文件，不算数。

财报文件至少要有：证券代码、科目、数值、报告期结束日、公开时点。公开时点要到日期；能到时点更好。没有公开时点的行不能进入信号。

成分文件至少要有：日期、证券代码、在当日是否在池内。只有一个没有日期的代码清单时，产品把它当成「生成日名单」，结论页必须警示幸存者偏差。

行业文件至少要有：日期、证券代码、分类体系和分类代码。没有日期的，不能打开行业中性。

价差文件可选。有的话至少要有：日期、证券代码、价差（用价格的比例或基点，文件里声明单位）。没有价差文件时，用第 2.2 节已定的成本假设。

文件路径和口径宣告进数据血缘。可实盘交接要能凭冻结下来的输入复现，不能只记一个以后会变的路径。见第 2.8 节。

### 2.6 Yahoo 与 AkShare

**已定。** Yahoo（美股、美国 ETF）和 AkShare（A 股，抓新浪、东财）都是内置源。M2 期间不下线；是否下线、何时下线，在 M2 出口评审时再议。它们不是默认选中的来源，用户要主动选。端到端验收仍然以本地文件为准。Yahoo 属于可选路径，只需保证不被破坏。

两者共用下面的规则：

1. 设置页显示为可用的内置源。界面文案不带日期，只写：「数据来自对公开网页的自动采集，未获数据方许可，仅供个人研究。」知情确认、按市场选源和旧研究补确认见第 2.6.1 节。勾选的话是：「我了解该数据未经许可，仅用于个人研究。」
2. 可以用它们开跑，也可以用它们满足数据覆盖门禁。用到的地方都要显眼标注「数据未经许可」：确认卡「将使用的数据」块、研究列表、结论页、研究记录和策略包。数据血缘记录来源名称。AkShare 还要记下上游是新浪还是东财。Yahoo 记下 yfinance。
3. 导出时，用了 Yahoo 或 AkShare 的策略包和研究记录包一律只放数据指纹，不提供「我有权再分发这些数据」的勾选。包里写明下游需自备有权使用的同口径数据。
4. 若下线，则：新研究和新版本不能再选这两个源；旧研究照常打开，重新验证只用冻结快照；继续迭代前必须换源并开新版；下线前要在界面上提前提示。M2 期间不执行这段。

**标签。** Yahoo 与 AkShare 的标签都定为「未经许可」，用同一套规则。这是用户 2026-10-19 的决定。理由：Yahoo 的使用条款禁止自动抓取，yfinance 是非官方接口；AkShare 抓取新浪、东财的公开网页，未获数据方许可。

A 股成本已定，见 [策略族 v1](./strategy-families-v1.md)：个股单边 20 bp，沿用 cost-v1；A 股 ETF 单边 5 bp。两者都是保守的产品假设，结论页要标注。M2 里可以新建并运行 A 股研究，但只能用现有的逐日 z 分数均值回归路径。用户要自己选 AkShare 并做知情确认。界面标「未经许可」，并提示「未模拟 T+1 与涨跌停，实际成交可能更差」。低波、股债再平衡、基本面因子、全天候的中国大陆版本不进 M2，列入第二批，在 M2 出口评审时再定。A 股均值回归不算五族验收的一部分。旧 A 股研究用冻结快照重新验证时，结果不变；开新一轮时用新成本。第一批不建模 T+1 和涨跌停。五族的端到端验收仍以美国本地文件为准。Yahoo 只保证现有路径不被破坏。

Yahoo 帮助页仍说明调整收盘含拆股和现金分红。用它做总回报时，沿用策略族规格第 6.5 节里已经写明的调整口径和坑。那一节不再表示产品不提供这个源。

### 2.6.1 未经许可来源的主动选择

知情确认只适用于 Yahoo 与 AkShare 这类未经许可的来源。有许可的账户仍用第 2.7 节的「我有权将该数据用于研究」，不套用 (a)。按市场选源和混池规则对所有来源生效。

**(a) 知情确认。** 按来源各确认一次。Yahoo 确认了，不等于 AkShare 也确认了。确认记在用户级，不是每个研究都要再确认一次。记录确认时间。设置页可以撤销；撤销后该来源回到未确认。已经开跑的那一版不因撤销而改写。之后再用这个来源，按未确认处理。

确认有两个入口，完成其中任一即算确认：

- 在设置页启用该来源时确认。
- 在确认卡里内联确认。

已经确认过的，确认卡只显示「已确认·日期」，不再重复问。

**(b) 按市场分别选源。** 确认卡的「将使用的数据」块按市场各占一行。每一行都要单独选定来源。哪个市场还没选，就显示「待选择」，并且不能开跑。不自动替用户选。按市场各占一行，是为之后若支持混合池留的位置。现在的新研究不允许把不同市场放进同一个池。遇到混池时的拆法见 (d)。

预填只适用于用户自己的来源：本地文件，以及用户已经配置的账户。这类来源可以预填成「建议」，但仍需用户点选确认。点选之前这一行仍是「待选择」，不能开跑。

未经许可的来源（Yahoo、AkShare）任何时候都不预填、不建议。某个市场只有这类来源可用时，这一行显示「待选择」，由用户主动选。

确认卡里已经选了来源，但该来源的知情确认还没勾，不能开跑。

**(c) 旧研究。** 这一条不用于旧的混池研究。混池见 (d)。其余旧研究：打开，以及用冻结快照重新验证，都不受本节影响。第一次继续迭代前，如果用户还没确认过该来源，在确认卡里补一次内联确认。一次勾选即可。不开新版，不算数据血缘变更，研究内容不变。没勾选不能开新一轮。查看、导出、重新验证和其他不开启新一轮的操作照常。

**(d) 新研究不混池；旧混池不继续迭代。** 新研究的池只能有一个市场。池里同时有美股和 A 股时，不能就这样开跑，也不能在这份研究里拆开继续。页面提供「按市场拆成两个研究」，生成两份草稿。这两份草稿不带 `derived_from`，试验轮数从零开始算。它们是新研究，各自选源，各自走 (a) 的确认。

旧混池复制出的草稿才写 `derived_from`，并继承已试轮数。下面这段不适用于新建研究当场拆出的那两份。

旧的混池研究按遗留中性处理。可以照常打开，也可以用冻结快照重新验证。不提供「继续迭代」，也不在这份旧研究里开新版。页面提示「请新建单市场研究」，并提供一键按市场把设定复制成两份草稿。草稿是新研究，各自选源，各自走 (a) 的确认。

草稿用字段 `derived_from` 记录来源。它记下旧研究的 id、版本，以及旧研究已经试过的轮数 N。默认是 null。null 表示这份研究不是从旧研究派生的，按遗留中性处理；缺这个字段不得当成「派生自某一份旧研究」。

旧混池的一键复制必须做到两件事：

1. 两份草稿都写入 `derived_from`。结论页和策略包的历史里都能看到「派生自旧研究 X」，X 用旧研究的 id，并带上版本。
2. 新研究显示旧研究已经试过的轮数。试验次数不从零重新计。

继承来的 N 不只用于显示。它计入累计试验次数 M，也就是 [#124](https://github.com/AlphaStrategyAI/alphaloop/pull/124) 的 cumulative M，并影响多重检验的门槛。拆池之后窗口键变了，也不能把 M 从 0 计。按市场拆成两份草稿时，两份都继承全部 N，不分摊。一份草稿自己后来新跑的轮次，只加在这一份的 M 上。

### 2.6.2 公开资料源

Crossref 和 SEC 全文检索归入新的一类：**公开资料源**。它们是公开的官方 API，不属于未经许可的自动采集。不放进第 2.2 节那五类行情和财报数据，也不替代「行情与总回报」。

它们与 EDGAR 共用同一个用户联系邮箱。没配邮箱时不调用，返回稳定错误码和参数，例如 `contact_email_missing`。界面按这个错误码显示当前语言的白话说明和下一步建议，例如「未配置联系邮箱，本次不查询 Crossref / SEC 全文」。原始技术信息只放在「技术详情」里。资料缺失时按现有规则如实处理：能缩量就记录，要跌破底线就停下来问，不用另一家资料源悄悄补上，也不把没查到写成已经有证据。

### 2.7 配置体验

设置页放在左栏第四项，路由为 `#/settings`，算对七屏的增补。先沿用 Tech Pulse 的卡片样式。设计小迪会补一张轻量稿用来对齐样式，不阻塞开发。数据源、大模型和界面语言是这一页里的分页。研究对话不收集密钥。界面语言的规则见第 4 节。

数据源页要能做完五件事：

1. **添加账户。** 选择类型：EDGAR，或本地 CSV。EDGAR 填写联系邮箱。本地 CSV 选择路径并宣告口径。第 2.5 节的五家数据商在 M2 显示「尚未对接」，不出现密钥框。
2. **测试连接。** 只用于已经对接、并且用户保存了密钥的账户，按第 1 节。成功时显示这个账户实际覆盖的数据类别，以及行情或财报能追溯到的历史长度。五家「尚未对接」的数据商不能测试连接。
3. **类别开关。** 用户勾选这个账户要用于哪些类别。测试没有返回的类别不能勾上。
4. **权利确认。** 一句必须勾选的话：「我有权将该数据用于研究。」不勾就不能把这个账户用于新建研究。勾选的时间和别名记入研究，不记密钥。
5. **停用。** 一版研究在开跑时冻结一次输入面板，同一版的各轮都复用它。停用只影响以后的新版本。已经开跑的那一版不因账户停用或密钥删除而改去联网重取。

M2 的五家数据商保持「尚未对接」：不存密钥、不测试连接、不绑定到研究。上面的账户步骤不把这五家当成已经可配置的源。

新建研究时，按第 2.3 节检查这一族的「必须」类别。缺任何一类，确认开跑不出现。对话里说明缺的是哪一类，并给出去设置功能里数据源页的入口。用户配好再回来，草稿还在。

确认卡在研究设定摘要旁增加一块**将使用的数据**。行情按市场各占一行，未经许可来源的选法和确认见第 2.6.1 节。其他类别仍按类一行：类别、源的类型、账户别名、测试时看到的历史长度、口径（总回报或价格；财报则是发布时点的来源）。没有这一块，不能开跑。有市场行显示「待选择」时，也不能开跑。

### 2.8 与门禁的关系

四关不放松，也不因为「用户自己的数据」而跳过。

- **数据覆盖**按这个源实际取到的历史和字段计算。总回报宣告缺失，覆盖就是不足。全天候仍不能早于 2006-02-03，也不能少一条腿。
- **PIT**仍要求信号只用当时已公开的信息。数据商若只给报告期、不给发布时点，基本面因子不能开跑。
- **待确认**包括换源和换代理。这是「数据血缘确认」，不是经济逻辑确认，不问「谁的钱」。卡片写明从哪个别名或哪只代理换到哪一、哪一类数据会变、历史长度变不变。同意后开新版。验证资格按新源重算。旧研究第一次继续迭代时补做的来源知情确认不是换源，见第 2.6.1 节，不开新版。
- **验证**不因为换了一家更「好看」的源而沿用旧结论。

研究进行中不得静默切换数据源，也不得在一个源失败时自动改用另一个已配置的源。失败按覆盖门禁处理：容忍度之内的收缩要记录；要跌破就停下来问。停下来时的选择是换源并开新版、缩小范围并开新版、提供本地文件，或停止。没有「先用另一家顶上」的选择。

策略包和研究记录包默认只放数据指纹：逐列哈希、行数、起止日、口径，不放数值。包内回测要求下游提供同口径文件，并按指纹校验。除 Yahoo 和 AkShare 外，用户可以在每次导出时单独勾选「我有权再分发这些数据」，勾选后才放数值。不勾选就只留指纹。用了 Yahoo 或 AkShare 的包不提供这个勾选，见第 2.6 节。包里仍写明：下游需自备同口径数据；本包不含密钥，也不附带数据商许可。勾选再分发时放进包里的数值，是当时那一版冻结输入的副本，不是一条以后会变的路径。

**累计 M 的窗口键。** 不按策略族拆。同一份数据上不同族的尝试都算进同一个累计 M，界面另给按族的细分。数据源那一段用「数据商标识 + 类别」，不含账户别名；同一家换账户不清零。自选池的窗口键要加上池的标识，用成员清单的哈希表示，避免不同的自选池共用一个累计 M。从混池复制出的草稿另加第 2.6.1 节的继承轮数 N：两份都把全部 N 计入自己的累计 M，并用于多重检验门槛，不因为新池的窗口键不同而从 0 起算。

## 3. 大模型

大模型只提出假设。收益、持仓、门禁和验证由确定性引擎计算。确定性引擎、门禁和 CI 不依赖大模型。离线测试用本机的假 OpenAI 兼容端点。没有配置大模型时，仍允许走确定性路径：确认卡提示「未配置大模型：判族按确定性规则，迭代按登记顺序」。这与交付收口里「外部大模型的抖动不能卡住这条路径」一致。

第一版里大模型参与的步骤只有下面四步：

1. **论点判族。** 只能在已支持族的封闭清单里选，并给出白话理由。确定性规则是底线。两者不一致时让用户选，不由模型单独定案。
2. **文献和资料摘要。**
3. **族内下一步。** 只能从预先登记的离散参数空间里挑候选，不能造新参数。
4. **审阅意见。** 只记录意见，不否决。审阅关仍由确定性 reviewer 把守。

这是本节判断换模型算哪一层的依据，也是产品设计里「研究方法可以自动推进、经济逻辑必须确认」的落点。

### 3.1 配置什么

设置功能的大模型页可以填写三项：

- **base url**：接入地址。允许填服务商的地址，也允许填本机或自建的地址。
- **api key**：按第 1 节存放。本机模型若不要密钥，此项可以空着，设置页写明「此地址不使用密钥」。
- **模型名**：调用时使用的名字。

第一版以 **OpenAI 兼容接口**为主：用这三项就能发起一次对话请求。本文不记载 Anthropic、Gemini 或其他协议的字段是否相同、路径是否相同。对其他协议的支持列为待定。

### 3.2 测试连接

按第 1 节。成功时白话写明：这个模型名在这个主机上可用。失败时白话写明原因，例如地址没有响应、密钥被拒绝、模型名不存在。不出现完整 api key。

测试只确认「叫得应」。它不代表模型的回答可以当成验证通过。

### 3.3 可复现，以及换模型算哪一层

每一轮研究记录记下当时用的模型：**模型名**，加上 **base url 的主机名和端口**。不记密钥，不记查询参数，不记路径里可能夹带的令牌。没有调用大模型的轮次，写明「本轮未调用大模型」。

一项研究进行中不得静默更换模型。只有用户在设置里主动更换才发生。更换当时就记下来：从哪个模型名和主机名换到哪个，何时换的。这条记录在实现栏内单列一行「大模型」，不放进策略模型族的「模型变更」栏，避免把换大模型和换策略族混为一谈。旧记录没有这一行，不受影响。

研究记录还可以额外保存：提示模板版本、请求参数（例如 temperature）、原始回复文本或其哈希。这些都不含密钥。它们用来看清「为什么提出这个假设」，不要求整段迭代路径逐位重现。

**换模型是实现层变更，不开新版，也不走经济逻辑确认。**

现有规则里，必须开新版的是经济逻辑（信号机制、目标市场、验证标准、策略族、主因子）和数据血缘（换数据源、换已定代理）。研究方法、建模方法、参数不开新版。大模型只负责提出假设，不负责把收益算出来，也不负责判定四关。换模型不改变赚谁的钱，不改变验证标准，也不改变进入确定性计算的数据。因此：

- 不因此弹出经济逻辑确认卡。
- 不因此重算或撤销可实盘交接资格。门禁仍只看确定性引擎的结果。
- 换完之后新提出的假设，仍要过原来的四关。模型换了，不能把没过的关变成过。

这和换数据源不同。换数据源改变确定性计算的输入，所以开新版。换模型不改变那些输入。

若用户同一次操作里还改了策略族、验证方法或数据源，那些仍按原规则单独确认。换模型不能代替那些确认。

### 3.4 隐私披露

设置页在保存之前，用白话列出会发往模型端的内容，以及不会发的内容。用户不确认这份说明，不能把该模型用于研究。

**会发往模型端：**

- 研究论点：大致原理和用户原话。原话按原样发送。原话里的代码会发出，隐私披露里要写明这一点。单独整理出的标的池代码清单不发送。
- 文献只发送公开的元数据和摘要（abstract），用来生成资料摘要。不发送全文。
- 供提出下一步假设用的结果摘要：哪一族、哪一关过或没过、关键参数。只发送当前这一轮所需的结果摘要，不是完整的行情序列，也不是完整迭代记录。
- 当前这一版的经济逻辑陈述，包括赚谁的钱。

**不会发往模型端：**

- 数据源密钥、大模型 api key、EDGAR 联系邮箱以外的密钥材料。联系邮箱只用于 EDGAR 的 User-Agent，不发给大模型。
- 原始行情全量、财报数值全量、本地数据文件的全文。这些只进确定性引擎。
- 策略包里的冻结数据副本。
- 持仓名单。单独整理出的标的池代码清单也不发送。用户原话里带出的代码除外，见上。
- 完整迭代记录。只发送当前这一轮所需的结果摘要。
- 文献全文。只发送公开的元数据和摘要。

只有回环地址算本机：localhost、127.0.0.0/8、::1。局域网地址（例如 192.168.x.x）算「不在本机」。回环地址上，设置页写明：**使用本地模型，上面会发送的内容不出本机。** 其他主机写明内容会发到该主机名。主机名用第 3.3 节的记法，不含密钥。

### 3.5 未配置或不可用

新建研究时，大模型未配置也可以开跑。确认卡提示「未配置大模型：判族按确定性规则，迭代按登记顺序」，并给出去设置功能里大模型页的入口。不把缺模型写成不能开跑。用户配置了模型但测试失败时，同样走这条确定性路径，确认卡改写「大模型不可用：判族按确定性规则，迭代按登记顺序」。

研究进行中模型不可用：研究进入**已暂停**。这仍是产品设计里的六种状态之一，不新造状态。界面如实说明原因，例如地址没有响应或密钥被拒绝。不静默改用另一个模型，也不假装研究还在跑。暂停期间不计入有效研究时间。用户修好原来的模型，或主动换成另一个并按第 3.3 节留下记录之后，按当前版本继续。换模型本身不开新版。

### 3.6 不同角色是否分开配置

第一版**不**为「提出假设」和「审阅」各配一个模型。设置里只有一套 base url、api key 和模型名。

分开配置列为待定。建议是：以后若要分开，仍然算实现层。每一轮记下该轮每个角色实际用的模型名和主机名，仍然不开新版，仍然不改门禁。第一版审阅关仍由确定性 reviewer 把守。大模型审阅只记录意见，不否决。审阅模型的输出不能代替确定性引擎的通过或失败，否则换模型就会改变哪一次尝试被接受。第一版不分开，是为了隐私披露和记录只有一份。

## 4. 界面语言

这是用户 2026-10-19 的决定：**走乙方案，属于 M2。** 范围是所有面向用户的文本，包括导出报告。由第三个开发 agent 专做。M2 总工期仍约 8 周。切换不改变研究结论。排期见第 4.5 节。术语对照表见 [i18n-glossary-v1.md](./i18n-glossary-v1.md)，状态是 W1 已锁定（产品定稿）。

### 4.1 默认与切换

- 设置里是三个选项：「跟随系统（当前：X）」「中文」「English」。「中文」和「English」始终用各自的写法。X 是此刻跟随系统会用的语言，只写成「中文」或「English」。
- 首次启动默认选中「跟随系统」。系统语言是 `zh-*` 时用中文，X 为「中文」。其他情况用英文，X 为「English」。取不到系统语言时也用英文。
- 用户选了「中文」或「English」之后，以该选择为准。用户随时可以再选回「跟随系统」。
- 「跟随系统」在每次启动时读取系统语言。用户重新选中这一项时，也立刻再读一次，并按读到的语言重绘。运行中系统语言变了，到下次启动才生效。
- 切换立即生效，不重启。当前页面、打开的弹窗和正在进行的研究界面都即时重绘。
- 语言设置存在本地偏好里，不写入研究记录。切换语言不改变任何判定、门禁、策略族归类或版本。不算逻辑变更，也不算实现变更。

### 4.2 要翻译的范围

下面这些都随当前界面语言切换：

- 界面、弹窗、空状态、确认卡、结论页、设置页、错误提示、术语表，以及方法库和策略族的显示名与说明。

**引擎错误。** 引擎返回稳定的错误码加参数。界面按错误码显示当前语言的白话说明和下一步建议。原始技术信息（例如 “error sending request for url…”）只放在可以展开的「技术详情」里，原样保留，不翻译，不再作为主文案。遇到未映射的错误码，显示当前语言的通用说明，详情里放原文。任何密钥都不得出现在详情里，沿用第 1 节。

**导出。** 导出包和报告里给人看的文字，用导出时的界面语言生成，并把语言写进包的元数据。这个语言字段是给人看的元数据，不算机器字段，不进入数据指纹。机器读的字段不跟语言变，包括字段名、族 id、枚举值和数据指纹。同一个策略分别用中文和英文导出，策略内容和指纹必须一致；两份包的语言字段可以不同。

**数字和日期。** 给人看的日期用本机时区，不固定 Asia/Shanghai。时区与界面语言无关：中文和英文用同一套规则。

- 只有日期：YYYY-MM-DD，不带时区。
- 带时间：YYYY-MM-DD HH:mm±HH:mm。偏移是数字，例如 `+08:00`。禁用 CST、EST 这类缩写。
- 读不到本机时区时，显示用 UTC，时间用 Z，写成 YYYY-MM-DD HH:mmZ。

不得省略年份，也不得用英文月份缩写。百分比和 bp 的写法不随语言变。避免切换语言后把数字读错。

研究记录、策略包和导出元数据里的机器时间戳一律是 UTC，用 ISO-8601，并以 Z 结尾。时区不进入数据指纹。换显示时区或换界面语言，不改变指纹。

### 4.3 不翻译的部分

- 用户自己写的论点和备注，原样显示。
- 已保存的研究记录、当时生成的大模型摘要和评审意见，原样显示，并标出生成时的语言。不自动翻译，也不自动重新生成。自动翻译或重新生成会改变记录，还会发生新的大模型调用。
- 旧记录里的论点、摘要和评审没有语言字段时，按遗留中性处理。显示「生成语言未记录」。不去推测语言。
- 结构化的部分按当前语言显示，包括记录里的门禁结果、族名和状态。这部分一律用 id 存储。
- 文献标题和摘要保留原文。
- 股票名称：代码始终显示。名称显示数据源给出的原名，不翻译。

**大模型新生成的内容跟随当前界面语言。** 发给模型的请求里写明输出语言，并把输出语言记入记录。策略族归类和族内下一步只返回 id，和界面语言无关。确定性路径不受语言影响。用户的原文仍按第 3.4 节原样发送，不先翻译。

### 4.4 定稿与词例

中文源文案和英文定稿由产品负责。量化术语的英文用业内通用说法，统一在术语表里维护中英对照。设计负责英文在界面上放得下。开发负责把文案抽取成词条。

已定词例：

| 中文 | English |
| --- | --- |
| 未经许可 | Unlicensed |
| 待选择 | Not selected |
| 尚未对接 | Not yet supported |
| 幸存者偏差 | Survivorship bias |
| 时点数据 | Point-in-time (PIT) |

其余核心术语的中英对照以 [i18n-glossary-v1.md](./i18n-glossary-v1.md) 为准。该表已在 W1 锁定，表内的词不允许用占位英文。

### 4.5 排期

排期跟 I0 / I1 对齐。

- **W1，对应 I0。** 产品交付术语中英对照表的定稿。
- **W2，对应 I1。** 开发抽取出词条之后，产品交付已有界面和错误码的英文定稿。
- 之后新增的词条，每个 PR 合并前补齐英文定稿。术语表里的词不允许用占位。
- 占位英文必须带占位标记。带标记的 PR 可以合并。I0-ci 统计占位数量并在 PR 里显示。M2 出口时占位必须清零。没有标记的缺失词条仍然让 CI 失败。

## 5. 验收标准

**数据源**

- 没有配置「必须」类别时，确认开跑不出现，并指出缺的类别和设置入口。
- 权利确认未勾选时，该账户不能被选进研究。
- 确认卡的「将使用的数据」与实际使用的别名一致。
- 研究运行中把行情源从 A 换成 B，若不经确认，持仓不得改按 B 计算。确认之后才是新版。
- A 源失败时，已配置的 B 源不会被自动拿来补。覆盖不足按原门禁停或收缩，并写明是 A 失败。
- 宣告为价格的本地文件不能让股债或全天候通过总回报口径。
- 财报文件没有公开时点时，基本面因子的 PIT 不通过。
- 全天候用已定的五只代码时，数据若早于 2006-02-03，不得把更早的一段算进覆盖。
- 策略包不含密钥，并写明下游需自备同口径数据。
- 五家数据商在设置页都显示「尚未对接」：不存密钥、不测试连接、不绑定。本地 CSV 和 EDGAR 可以配置。M2 没有 Parquet 导入。端到端验收以本地文件为准。构造样本的导出没有可实盘策略包入口。
- Yahoo 和 AkShare 都显示为内置源，不是默认选中。界面文案不带日期，只写：「数据来自对公开网页的自动采集，未获数据方许可，仅供个人研究。」
- 设置页数据源的首次启动引导是 09a，标题为「选一个数据源开始」。引导正文是：「除 Yahoo（美股）与 AkShare（A 股）两个未经许可的来源外，不内置行情源。」
- 知情确认按来源各一次，记在用户级。确认 Yahoo 之后再开一个用 Yahoo 的研究，确认卡只显示「已确认·日期」，不再询问。AkShare 仍要单独确认。记录确认时间。设置页可以撤销；撤销后下一次使用重新询问。已经开跑的那一版不因撤销而改写。
- 确认有两个入口：设置页启用时确认，或确认卡内联确认。两个入口写入同一条用户级确认。
- 「将使用的数据」按市场各占一行。未选的行显示「待选择」，确认开跑不能提交。不自动替用户选定来源。
- 只有本地文件或用户已配置的账户可以预填为「建议」。点选之前仍是「待选择」。Yahoo 和 AkShare 不会出现在预填或建议里。某个市场只有这两个来源时，该行显示「待选择」。
- 确认卡已经选了未经许可的来源，但知情确认还没勾时，不能开跑。
- 新研究的池里同时有美股和 A 股时，不能就这样开跑。页面有「按市场拆成两个研究」。拆出的两份草稿 `derived_from` 为 null，试验轮数和累计 M 都从零开始。
- M2 可以新建并运行 A 股研究，但只能用现有的逐日 z 分数均值回归路径。用户要自己选 AkShare 并做知情确认。成本是个股单边 20 bp、A 股 ETF 单边 5 bp。界面标「未经许可」，并提示「未模拟 T+1 与涨跌停，实际成交可能更差」。低波、股债再平衡、基本面因子、全天候的中国大陆版本不能开跑。A 股均值回归不算五族验收。旧 A 股研究用冻结快照重新验证时，结果与冻结时一致；开新一轮时改用新成本。
- 非混池的旧研究可以打开，也可以用冻结快照重新验证，不要求先做知情确认。第一次继续迭代前若该来源未确认，确认卡给出一次内联勾选。勾选后不开新版，版本号不变，数据血缘记录不把这次勾选写成换源，研究内容与勾选前相同。未勾选时不能开新一轮；查看、导出和重新验证仍可用。
- 旧混池研究可以打开，也可以用冻结快照重新验证。页面没有「继续迭代」，也不会在这份旧研究里开出新版。页面有「请新建单市场研究」，以及一键复制成美股、A 股两份草稿。
- 这两份草稿的 `derived_from` 都不是 null，且都记下同一旧研究的 id、版本和全部已试轮数 N。不是派生研究的 `derived_from` 为 null。结论页和策略包历史都能读到「派生自旧研究 X」。
- 两份草稿显示的已试轮数都是全部 N，不是各一半。各自的累计 M 都包含全部 N，并因此提高多重检验门槛。一份草稿新跑一轮，只增加这一份的 M。
- 用了其中任一源的确认卡、研究列表、结论页、研究记录和策略包都有「数据未经许可」。血缘写明 Yahoo/yfinance，或 AkShare 以及新浪或东财。
- 用了 Yahoo 或 AkShare 的导出只有指纹，没有「我有权再分发」勾选。
- Yahoo 路径不被破坏即可，不作为端到端验收的必经路径。

**大模型**

- 未配置或测试未成功时，确认开跑仍然出现。确认卡写「未配置大模型：判族按确定性规则，迭代按登记顺序」，或「大模型不可用」的对应句子，并指向大模型页。
- 测试成功时界面写明该模型可用；失败时是白话原因，且没有 api key。
- 研究记录里有模型名和主机名，没有密钥，没有查询参数。
- 研究进行中不出现未经用户操作的模型更换。
- 用户主动更换后，实现栏内「大模型」一行有前后模型名和主机名，不写在策略模型族的「模型变更」栏。版本号不因此增加。四关的通过条件与更换前相同。大模型审阅意见不能把一次尝试判成不通过。
- 模型中途不可用时，状态变为已暂停，有效研究时间停止增加，且没有改用另一个模型的结果。
- 保存前能看到会发送和不会发送的清单。本机地址上写明内容不出本机。
- 发给模型的内容里没有持仓名单，没有完整迭代记录，没有文献全文。文献只有公开元数据和摘要。结果摘要只覆盖当前这一轮。

**共用**

- 在日志、策略包、迭代记录和测试失败说明里搜索数据源密钥和大模型 api key，结果为空。

**界面语言**

- (a) CI 扫描：词条文件之外的界面源码里，不得有中文硬编码，也不得有面向用户的英文硬编码。
- (b) 中英两套词条的 key 集合完全一致。没有占位标记的缺失词条让 CI 失败。运行时万一缺词条，显示另一种语言的文案，绝不显示 key。
- (c) 引擎的所有错误码都有中英白话说明。主文案里不出现原始英文异常。技术详情里的原文不含密钥。
- (d) 在 1280 宽度下切到英文，关键页面不得截断，换行不得撑破布局。关键页面包括：设置 09 和 10、确认卡、结论页、导出页、错误弹窗。
- (e) 在关键页面运行时来回切换语言，立即生效，状态不丢。当前页面、打开的弹窗和正在进行的研究界面都重绘。判定、门禁、族归类和版本号不变。
- (f) 同一个策略分别用中文和英文导出，机器字段和指纹完全一致。这里的机器字段和指纹不包括导出元数据里的语言字段，也不包括给人看的时区。这两项可以不同，且不进入指纹。研究记录、策略包和导出元数据里的机器时间戳一律是 UTC，ISO-8601，并以 Z 结尾。给人看的文字用导出时的界面语言。百分比和 bp 的写法不变。
- 给人看的日期用本机时区，不固定 Asia/Shanghai，也与界面语言无关。只有日期时是 YYYY-MM-DD，不带时区。带时间时是 YYYY-MM-DD HH:mm±HH:mm，偏移用数字，不得写成 CST、EST 或其他字母缩写。读不到本机时区时，显示用 UTC，时间写成 YYYY-MM-DD HH:mmZ。不得省略年份，也不得出现 Jan 这类英文月份缩写。中文界面同样遵守。
- (g) 占位英文必须带占位标记。带标记的 PR 可以合并。I0-ci 统计占位数量并在 PR 里显示。M2 出口时占位必须清零，包括导出报告。没有标记的缺失词条仍然让 CI 失败。术语表里的词不允许用占位。
- 语言选项只有三个：「跟随系统（当前：X）」「中文」「English」。首次启动选中「跟随系统」。系统是 `zh-*` 时界面为中文且 X 为「中文」；其他系统语言，以及取不到系统语言时，界面为英文且 X 为「English」。每次启动、以及重新选中「跟随系统」时，都读取一次系统语言并立即重绘。运行中系统语言变了，界面保持到下次启动。语言存在本地偏好里，不出现在研究记录中。
- 用户自己写的论点、备注、已保存的大模型摘要和评审意见、文献标题和摘要、股票名称都保持原文。股票代码始终显示。已保存的模型文字标出生成时的语言，不自动翻译，也不自动重新生成。没有语言字段的旧论点、摘要和评审显示「生成语言未记录」，不把正文语言猜成中文或英文。
- 新的大模型输出跟随当前界面语言。请求里写明输出语言，记录里记下输出语言。族归类和族内下一步只返回 id。用户原文按第 3.4 节原样发送。

## 6. 已知限制

- 产品不代理购买数据，也不审查用户勾选的「我有权使用」是否在法律上成立。
- 五家数据商的价格和字段会变。第 2.5 节是 2026-10-19 的核对，不是长期价目。
- 许多家没有公开保证时点财报或历史买卖价差。基本面因子不能靠这些不确定项开跑。
- EDGAR 不提供总回报，也解决不了股票池的幸存者偏差。
- 个股 5 bp 仍是产品假设。价差源接上之后可以在结论页对照，但不自动改掉已定的 5 bp，除非用户确认换成本假设并开新版。那是验证标准或成本假设的变更。
- 设置页数据源首次启动引导 09a 的标题是「选一个数据源开始」，正文是：「除 Yahoo（美股）与 AkShare（A 股）两个未经许可的来源外，不内置行情源。」界面说明不带日期，只写：「数据来自对公开网页的自动采集，未获数据方许可，仅供个人研究。」端到端验收以本地文件为准。构造样本不得导出可实盘策略包。Yahoo 与 AkShare 都标「未经许可」，是用户 2026-10-19 的决定。
- 大模型的回答不是验证。换模型不改变门禁，也不保证下一轮假设更好。
- 本文只规定 OpenAI 兼容这一种接口。其他协议未核对。
