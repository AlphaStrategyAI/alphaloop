## 0. 这份文档是什么

这是 alphaloop 的 **V1 交付收口**：产品行为已经写在设计里之后，锁住第一版实际交到哪里、哪些铁律不许往后挪、哪些野心明确缓做。

上游是[产品定位](./product-positioning.md)。行为规格以[产品设计 v0.0.1](./product-design-v0_0_1.md) 为准，含其中的 B1–B6。交互表面仍是[界面设计](./ui-design-v0_0_1.md) 的 Night 七屏。本文不另写一套产品行为，也不另起信息架构。

它**不是**新的产品设计，也**不是**实现方案。某个行为怎么定义，回产品设计；第一版必须交什么、可以不交什么，以本文为准。铁律与行为定义以产品设计为准；交付范围以本文为准。

**已经接上的界面，不要再当成缺口。** main 在 PR #120、#121 之后，桌面已经接上不少铁律槽位：时点第四关、确认卡上的「谁付钱」与确认前证据、轮次列，以及确认开跑上「再改改」的解锁。收口谈的是交付是否诚实——工作台里的结论、指标、证据、试验次数必须来自真实研究闭环——不是把这些槽位重新写成还没做。

## 1. 铁律（不许后移）

下面这些整包留在 V1。分期只排野心，不排铁律。

### 1.1 B1–B6

| 编号 | 铁律 | V1 必须守住的语义 |
| --- | --- | --- |
| B1 | 时点 / 反前视是第四关 | 「时点 / 前视一致性」是可实盘交接的第四条资格。未执行或未通过，不能导出可实盘策略包。检查有没有做、结论是什么，写进数据出处。 |
| B2 | 露出试验次数 | 每一轮写清评估了多少候选、通过了几个、当前结论来自第几次尝试。策略包里的迭代历史带着同样的次数，不能只留最终那一个结论。 |
| B3 | 逻辑与实现分栏 | 每一轮分两栏：经济 / 交易逻辑陈述，以及实现与参数变化。逻辑陈述相对上一轮发生实质变化，必须确认并开新版，不得算作自动小迭代。 |
| B4 | 确认卡：谁的钱，以及证据引用 | 必须问「这个逻辑赚的是谁的钱？对方为什么会继续付？」。可以不答，记录为「未作答」。「为什么要改」只能引用确认前已经写下的证据引用（EvidenceRef），禁止用确认之后的叙事回填。 |
| B5 | 异常好的结果先摊证据 | 相对基线异常好或异常新奇的结果，先展开数据出处、覆盖是否缩过、试了多少次、用的哪份验证定义，再给结论文案。呈现是高怀疑的检查清单，不是庆祝。 |
| B6 | 多维 Scorecard，定义不可回改 | 验证方法按多个维度写清检验什么、通过阈值、失败时用户看到什么。旧定义的维度语义不能事后改写；要改，就新定义。 |

### 1.2 一并保留的既有铁律

- **数据覆盖自动缩量有底线。** 只在用户认下的最低覆盖容忍度之内自动缩，并且记下来。要跌破底线，停下来问。
- **可实盘交接有门槛。** 策略包交出去之前，资格条件必须同时成立（见产品设计 §3.7，含上面的第四关）。缺任何一条，不提供可实盘策略包导出。
- **alphaloop 自己不下单。** 交接物是策略包。不下单、不接券商、不跑模拟盘或实盘。
- **本机优先的工坊。** 研究跑在用户自己的机器上，不是托管云服务。
- **桌面是主交互，CLI 不是。** 完整交互在桌面应用。CLI 的封闭清单只有启动和查看状态。

## 2. 第一版必达

一条正确、能用、以后还能加长的路径。做到这些，V1 才算交了。

| 必达 | 交到什么程度 |
| --- | --- |
| 一条真实研究闭环 | 不是把关键词规则的草稿对话当作唯一的大脑。运行中和已完成的工作台，被可检查的结论、指标、证据、试验次数填满，这些内容来自这条闭环。 |
| 确认流按设计走完 | 「谁的钱」必须问、可以不答；「为什么」只引用确认前的 EvidenceRef；逻辑 / 实现分栏按产品设计呈现。 |
| 完成态导出含全部门槛 | 已完成研究的可实盘导出资格包含全部交接门槛，含时点第四关。任一关不成立，不导出可实盘策略包，并写明缺的是哪一条。 |
| 一条诚实的端到端 | 产品里已经有的一个策略族即可。MeanReversion 类可以作为 V1 这一族。去掉假装研究已经发生的占位文案和空标题。 |
| 策略包能被别人拿走执行 | V1 交接的是自足策略包，加上冻结的数据与验证。下游自己实现 `ExecutionPort`。包里可以带 `ExecutionPort` / `NotImplementedBroker` 占位，这符合不下单的铁律。alphaloop 不交付可直连券商的执行器。 |
| Night 七屏仍是交互表面 | 研究列表、草稿、确认开跑、运行中、等待确认、已完成、验证方法库。不为 V1 新做一套信息架构。 |

草稿对话在 V1 可以保持薄。深度来自结构化研究闭环，不来自把入口做成开放式长对话。

### 2.1 可测 Done

下面五条同时成立，P0 / 第一版必达才算交。缺任何一条，不算这条诚实路径做完。

| # | Done |
| --- | --- |
| 1 | 锁定五项研究设定，跑通至少一轮真实 `ResearchLoop`（不是 `FakeBuilder`），研究到达已完成（`COMPLETED`）。 |
| 2 | 运行中 / 已完成工作台上的字段全部来自这一轮闭环。没有空标题，没有假指标。 |
| 3 | 四条可实盘资格全部通过，含时点第四关，才能导出 `strategy_pack`。缺任何一关，只能导出 `research_record`，并写明缺的是哪一关。 |
| 4 | 导出的 zip 能通过 `contracts/strategy-pack.schema.json` 校验，且 `live_handoff_eligible: true`。 |
| 5 | 这条诚实路径钉一个确定性 reviewer（固定 Pass/Fail 策略），接在现有 review 关上。外部大模型的抖动不能卡住 V1 唯一的这条路径。 |

### 2.2 P0 落在现有契约上

P0 使用已经在产品里的 `RoundBuilder` / `ResearchLoop`、`VerifierResult` / `pit.consistency`、`strategy_pack_eligibility`，以及 `contracts/strategy-pack.schema.json`。不为 V1 再开第二条研究路径，也不为这一版新造一套抽象。

### 2.3 数据口验收（写死）

- CI 可以用 fixture 面板。
- **至少一条被接受的路径必须走真实的 `DataPort` / `MaterialPort`。** 只走 Fake 或 fixture，不算数。
- 只靠 fixture 的演示，不算 §2.1 的诚实端到端 Done。

## 3. 缓做 / 砍出第一版

这些不进入 V1 的交付承诺。有后续期的，按第 4 节排；没有期的，留在第 5 节，不悄悄加回 P0。

| 缓做 | 落到哪 |
| --- | --- |
| 开放式大模型对话研究作为主入口 | 不作为 V1 主入口。有界的对话与归档升级在 P1，且 P1 仍不是无监督挖掘。 |
| 多策略族挖掘、无监督大规模因子挖掘、自由 Python agent 作为产品默认 | 不作为 V1 的默认形态，也不排进 P0–P3 的默认路径。 |
| 研究记忆、生产级试验骨架（harness）、AxiomQ 式大规模假设工厂 | V1 不做。可重复的评估与缓存式规模化在 P3，仍然不是应用内交易。 |
| 把策略空间扩过 V1 这一族 | 第二个策略族，以及方法库往第二族的扩展，在 P2。 |
| 行情终端、运维控制台、在 alphaloop 内下实盘单 | 不进入 V1，也不排进 P0–P3。 |

## 4. 分期

| 期 | 交什么 | 谁来做 |
| --- | --- | --- |
| **P0** | 真实研究闭环填满可检查的工作台；去掉占位；一条 MeanReversion 类的端到端路径；导出门槛含时点第四关，端到端强制成立。验收以 §2.1 为准，契约以 §2.2 为准，数据口以 §2.3 为准。界面只在现有屏缺少真实字段的槽位时才动，不为 Night 壳做视觉大改。 | 小牛工程为主。小迪只在屏幕没有真实字段的槽位时介入。 |
| **P1** | 对话升级，加上消息与归档，使入口不再只是关键词规则。仍然不是开放式、无监督的挖掘。 | 后续期，不提前进 V1。 |
| **P2** | 第二个策略族，以及方法库在这一范围上的扩展。 | 后续期，不提前进 V1。 |
| **P3** | 研究记忆，以及确定性的评估与缓存，用来把同一套研究规模做大（harness）。应用内仍然不下实盘单。 | 后续期，不提前进 V1。 |

P0 是 V1 的工程主体。P1–P3 是收口之后的顺序，不是 V1 的隐藏范围。

## 5. 非目标

下面这些不是 V1 要交付的东西。交易和终端类也不排进 P0–P3：

- **不是实盘交易终端，也不交付可直连券商的执行器。** 不下单、不接券商、不管账户、不跑模拟盘。下游拿到的是策略包，自己实现 `ExecutionPort`。
- **V1 不是多资产大规模挖掘工厂。** 第一版只承诺一个策略族上的一条诚实路径。
- **不替换 Night 七屏。** 不为 V1 新做信息架构、不把桌面改成终端皮肤。
- **CLI 不是主界面。** 仍然只有启动和查看状态。
- **不宣称产品设计里的想象段落已经在 V1 交齐。** 更厚的自主对话、方法库随用随厚、第二个策略族、研究记忆与规模化试验骨架，都留在对应分期之后。设计文档继续描述产品行为；第一版是否算交齐，以本文的必达、§2.1 和分期为准。

## 已知限制（P0 过渡）

**验证未通过时的「诚实停止」：** 在 P0 中，若冻结验证方法集未全部通过，且系统推断的下一步是实现层参数/模型小改（非经济逻辑或 B3 逻辑变更），`ResearchLoop` 会到达 `COMPLETED` 而**不会**自动继续 PARAM 迭代。这不是长期默认行为；后续应改为有预算的自动迭代（例如最大试验次数上限）。经济/覆盖/逻辑类改动仍必须走 `REQUEST_CONFIRM`。用户可在已完成工作台手动点「继续迭代」开下一轮，试验次数递增，早前失败轮次保留；验证阈值不因「继续」而放宽。
