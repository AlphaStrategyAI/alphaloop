# Dataset CSV rejects per-symbol OHLCV tables

**Date:** 2026-08-20
**Status:** Approved for this implementation cycle
**Scope:** `parquet_bytes_from_csv` fail-closed when columns are a
bar table (`open`/`high`/`low`/`close`). CLI `alphaloop dataset` and
`cache_dataset_bytes` (console picker) use that helper. Not a new
hard gate. Not inventing `FOUND`. Not auto-submit. Not heritage
`alphaloop fetch` network I/O. Not converting Close into a ticker.
Not unfreezing `webui/`. Not soak. Not \(N_{\mathrm{eff}}\). Not
restyling chrome.

## 1. Why this cycle exists

Overnight snapshots are wide close-only: DatetimeIndex, columns =
asset ids (packaged `ds_example`: `AAPL`, `MSFT`, `SPY`). Heritage
`alphaloop fetch` writes a **per-symbol OHLCV** CSV (`open`, `high`,
`low`, `close`, `volume`). That file is readable CSV, so
`parquet_bytes_from_csv` currently caches those bar names as if they
were tickers. Walk-forward then researches `open` vs `close` instead
of AAPL vs MSFT. Bailey / López de Prado: name the evaluated series.
Fail closed; do not invent a universe from OHLC fields.

## 2. Best-practice basis

1. **Same shape as `ds_example`.** Asset-id columns pass. Bar-table
   columns do not.
2. **Detect the fetch/Yahoo schema.** After parse, lowercased column
   names that include `open`, `high`, `low`, and `close` are OHLCV.
   Extra `volume` / `adj close` do not make it wide close-only.
3. **Do not reshape.** Do not pick the Close column and invent a
   ticker. That would be a second schema and a silent fetch adapter.
4. **Preserve the reason.** CLI stderr and `cache_dataset_bytes` MUST
   keep `ohlcv` in the `DatasetRejected` message. Do not wrap it as
   generic `parquet or csv`.
5. **No job, no alpha.** MUST NOT print `FOUND`. MUST NOT fetch.

## 3. In-scope requirements

### R1. Detection

In `parquet_bytes_from_csv`, after a successful `read_csv` and before
`to_parquet`, if

```
{"open", "high", "low", "close"} <= {str(c).strip().lower() for c in frame.columns}
```

raise `DatasetRejected` whose message contains `ohlcv` and
`close-only`.

Title-case Yahoo columns (`Open` … `Close`) match after `.lower()`.

### R2. Call sites

`cache_dataset_file` (`.csv` suffix) and `cache_dataset_bytes` MUST
propagate that `DatasetRejected`. `cache_dataset_bytes` MAY still wrap
unreadable/empty CSV as `parquet or csv`; it MUST NOT wrap an OHLCV
rejection.

### R3. CLI

`alphaloop dataset PATH` on an OHLCV CSV exits 2. Stderr contains
`ohlcv`. Stdout does not contain `FOUND`. Wide close-only CSV still
exit 0.

### R4. Docs

`docs/cli.md` MUST say per-symbol OHLCV is rejected. Skill MAY. Help /
`HOST_CONSTRAINT` / EXAMPLE_SPEC unchanged.

## 4. Out of scope

- Implementing `alphaloop fetch` → wide close-only. Auto-submit.
  Soak. \(N_{\mathrm{eff}}\). FakeWorker in morning e2e. Unfreezing
  `webui/`. Restyling chrome. Changing parquet-magic `put_dataset_bytes`.

## 5. Acceptance

- `parquet_bytes_from_csv` on open/high/low/close (+ optional volume)
  raises `DatasetRejected` matching `ohlcv`.
- Wide `AAPL,MSFT,SPY` CSV still caches.
- CLI OHLCV CSV: exit 2, stderr `ohlcv`, no `FOUND`.
- `docs/cli.md` mentions OHLCV rejection.
