## What works in the sandbox

- **CCXT** (3/3 tests pass): hits real OKX API, returns BTC/USDT
  and ETH/USDT 5-day data. **No proxy, no auth, low rate limits.**
  This is the only data source that **can be fully verified in
  the sandbox**.
- **Invalid symbol tests** for yahoo, akshare, ccxt: all pass —
  they verify that `DataSourceError` is raised on bad input.
  These work without any network call succeeding.

## What doesn't work in the sandbox

- **Yahoo Finance**: 429 rate-limited within seconds. The 5-day
  window used in tests should be light enough, but Yahoo is
  aggressive about anonymous clients. Tests will work in CI
  with a Yahoo API key, or from a non-flagged IP.
- **AKShare**: Sandbox has an HTTP proxy env var set; akshare
  goes through `push2his.eastmoney.com` which the proxy refuses.
  A direct smoke test (without proxy) works, but pytest inherits
  the proxy env, so it fails. This is a **sandbox config issue,
  not a code issue**. Locally without `http_proxy`/`https_proxy`
  set, akshare integration tests should pass.
- **OpenBBSource**: not exported from `openstrategy.data`. This
  is a known v1.1.2 gap (not in this milestone's scope; per
  v1.1 路线图 it's an OpenBB wire-in task). Tests are marked
  `pytest.xfail` so they show the expected state.

## Why Commander did this directly

The v1.1.1 retro's closing note said:

> "Consider not delegating at all for short tasks. v1.1.1 is maybe
> 4 hours of work if I do it myself. The cost of three rounds
> of dispatch + recovery exceeded the cost of direct execution."

v1.1.2 was even shorter than v1.1.1: ~30 min of focused work
(write 4 test files + 1 unit test patch + verify). The cost
model:

| Approach | Time | Risk |
|---|---|---|
| Dispatch 1 worker (v1.1.1 model) | 5-15 min dispatch + risk of "wrote file, didn't run" | High |
| Direct execution | 30 min, deterministic | Low |

Direct execution won. The `commander-delegate` skill was
**consulted as a checklist** (verify step 1-6) but the skill's
own closing note says "consider not delegating at all for short
tasks" — v1.1.2 fits.

## v1.1.2 Decisions

### Decision 1: Make tests runnable in the sandbox, not just on user machine

I considered writing tests that *only* work on a user machine
(or in CI) and skipping the sandbox verify entirely. Rejected
because v1.1 路线图 says "用户本地或 CI 跑才能完整 verify" —
but v1.1.2's *deliverable* is "test harness exists", not "all
tests pass everywhere". The harness exists; what passes depends
on environment.

### Decision 2: Use `pytest.xfail` for OpenBB

OpenBBSource not being importable is a known gap. Two options:

1. Skip the tests silently (CI looks green but tests don't run)
2. Mark them `xfail` (CI shows they're expected to fail; when
   the gap is fixed in v1.1.3, they become XPASS = signal to
   remove the marker)

Chose xfail because option 2 is the honest signal.

### Decision 3: Patch the akshare "not installed" unit test

The v1.0 unit test `test_akshare_not_installed_raises` was
designed for an environment without akshare. After v1.1.2
installs akshare to run integration tests, the unit test
fails. I patched it to skip when akshare is installed.

The patch is **honest** about what it does ("if you have
akshare, this test can't run; if you don't, it can"). It does
not pretend the install path doesn't exist.

## What v1.1.2 actually enables for v1.1.3

- **CI** can run `OPENSTRATEGY_INTEGRATION=1 pytest` and verify
  the integration tests that the sandbox can't (yahoo, akshare

  v1.1.3 can address it (or leave it for v2.0).

  tests locally; the unit suite is unaffected.
