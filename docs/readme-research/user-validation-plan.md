# 小规模真人验证方案

这是计划，不是已经发生的访谈。不要把评审角色 A–E 的输出填进这里。

## 找谁

4 到 6 人，彼此不讨论。两组各半：

1. 最近三个月用 Python 或表格做过美股或 A 股日频回测的人。会读中文。不是本仓库的作者或代理提交者。
2. 主要用聚宽或米筐、没有在本机装过回测库的人。同样会读中文。

不找：只想要买卖建议的人、机构采购委员会（0.2.0 没有可采购的支持合同）、已经参与这个仓库内部规格讨论的人。

## 任务

每人 40 分钟，屏幕共享，中途不提示。材料只有 GitHub 上的 README，不给 `docs/readme-research/`。

1. 用自己的话说明这个软件是给谁的、做完一项研究会得到什么、它不做什么。
2. 判断自己会不会做下一步。下一步只能是：克隆并启动引擎、放弃、或改用 README 里点名的某个替代品。记录选了哪一个。
3. 指出一处不敢相信的句子，以及需要看到什么才相信。
4. 若时间允许，按「最快路径」做到 `status` 打出 JSON 为止。不要求打包侧车。记录卡在哪一条命令。

## 观察什么

- 是否把「只跑均值回归」读成「能做任何策略」。
- 是否把历史回测读成收益承诺。
- 是否注意到 Yahoo / AkShare 的许可还没有按规格告知。
- 是否以为有安装包或有人提供付费支持。
- 第一处停下来的命令。

## 怎样算对 README 有用

若两组里各有两人不能复述「只做均值回归、不下单、没有付费」，首屏还要改。若会做回测的人停在侧车构建之前，最快路径还要改。这些标准用于下一次修改，本次交付不假装已经测过。
