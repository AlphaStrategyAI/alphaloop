## 对照项

| 对照 | alphaloop 0.2.0 | 典型差别 |
| --- | --- | --- |
| 研究跑在哪 | 本机 SQLite 与导出 zip | 聚宽、米筐浏览器研究在对方服务器。LEAN 两边都有。脚本在本机 |
| 能跑的策略 | 仅截面均值回归 | 上表其余工具由用户自己写策略，或平台提供更宽的 API。不是「它们没有均值回归」 |
| 试验次数 | 默认预算与窗口累计写入记录 | 没有在其余工具的文档里看到同一套「窗口累计 M」。缺失不等于它们没有别的防过拟合工具 |
| 前视 | 信号延迟一根 bar；资料发布日检查；池子时点与复权不在检查内 | 聚宽文档把一部分未来函数交给用户开关。自写代码完全靠习惯 |
| 下单 | 不做 | backtrader、LEAN 云、聚宽、米筐企业版都把交易或模拟放进产品范围 |
| 许可 | 代码 MIT；行情许可未在界面完成规格要求的告知 | vectorbt 有 Commons Clause；backtrader 是 GPL；云平台是专有服务条款 |
| 获取成本 | 源码构建，无安装包 | 云平台打开浏览器就能跑，这是继续用它们的具体理由 |

## 继续用现有方案的理由（有依据，不是劝退文案）

- 需要券商或模拟盘：0.2.0 不做。
- 需要低波、股债、基本面、全天候：规格有，代码拒绝开跑。
- 需要扫大量参数：vectorbt 的 README 把这件事当成主路径；alphaloop 的自动迭代只加回看天数。
- 不想在本机装 Rust、WebKit 和 PyInstaller：聚宽、米筐用浏览器。

## 参考 README，不模仿口号

见台账 E37。写进 alphaloop README 的是：首屏一个受众、一个任务、一个下一步；命令旁放一次真实的 `status` JSON；写明维护边界（什么还不能跑）。不写的是：实时行情算出来的收益、PRO 升级、以及靠机构品牌才成立的「平台」一词。
