### 6 项验收(`docs/v1.0-acceptance-report.md`)

| # | 验收问题 | 工具 | 结果 | 含义 |
|---|----------|------|------|------|
| 1 | Overfitting? | Deflated Sharpe Ratio (DSR) | **PASS** | DSR P-value = 0.000,observed SR 0.518 ≫ expected max SR 0.028 |
| 2 | Data source consistency? | yahoo vs akshare diff | **PASS** | 1500 bars overlap, P95 相对误差 < 0.1% |
| 3 | Out-of-sample valid? | Walk-forward CV | **PASS** | wf-cv 正常 fold,无 look-ahead |
| 4 | > random? | Block-shuffled baseline + max-drawdown | **FAIL** | 合成宇宙无真实信号,FAIL 是诊断正确性证明 |
| 5 | > buy & hold? | Same-window B&H Sharpe | **FAIL**(在 demo 上)/ **MET**(在因子对比上) | 10 因子 demo: **4/10** 跑赢 B&H(≥3 阈值满足) |
| 6 | > SPY buy & hold? | Same-window SPY Sharpe | **FAIL** | 同 #4,合成数据无 alpha |

**结论**:
- v1.0 ships as **honest-validation infrastructure**, not as promised alpha.
- FAILs are **correctly reporting** that the synthetic universe has no signal.
- 一个在合成数据上跑赢 SPY/B&H/random 的策略 → 那是 bug,不是特性。
- 4/9 alpha 因子在合成数据上跑赢 B&H → acceptance #5 met。

## 4. 关于上游独有内容的处理

上游的 `backend/`(FastAPI + 富途实盘)、`frontend/`(React + i18n 12 国)、`docker/`(生产部署)、`docs/education/`(教育内容) **不属于本地 v1.0 的范畴**:

- 本地 v1.0 的目标([`wiki/concepts/openstrategy v1.0 goal.md`])是"honest verifiable quant research framework" — 纯研究工具,不是 SaaS 产品。
- 上游是商业化 Web App(product-grade,Phase 1-4 完整,有 CORS / SSL / K8s / 12 国 i18n / 教育内容 / 富途对接)→ 那是另一个项目的工作量(估计 10+ 人月)。
- 直接合并会: (a) 引入富途实盘 SDK(违反本地 hard boundary #1 "no live trading without explicit opt-in"); (b) 引入 React + Node.js toolchain(破坏"single Python package" monorepo 约定); (c) 把 v1.0 从研究工具变成 SaaS(超出 v1.0 scope)。

**建议**:
- 如果用户想从本地 v1.0 → 上游式 SaaS:v2.0 / v3.0 scope,需单独规划
- 如果用户想把上游的某些**纯 Python 改进**(比如数据源 bugfix、CLI 子命令优化)merge 进来:case-by-case,逐项 review
- **当前 PR/merge 上游 master 的工作不做**(per skill pitfall:"user 取消过 GitHub 推送" — 同样的谨慎应延续到 PR)
