# 用对话驱动一项投资策略研究

技术设计 · 2026-11-01 · 适用基线 `main@5866c23`，桌面与引擎 0.9.5。本文中的接口、数据表、阈值和交互是拟议设计；第 2 节单列本次核实的现状。[实施计划](../plans/2026-11-01-dialogue-driven-strategy-research.md)

个人用户可以把一个还没想清楚的投资假设交给自己的电脑。桌面会帮他把话说清，展示实际要检验的策略，取得授权，然后在预算内持续查资料、模拟、验证和调整。用户回到同一条对话，可以问一项结论怎么来的，改变经济假设，重验一轮，或者带走策略包和失败记录。首条纵向交付使用美股或 A 股日频均值回归，把从第一句话到最后一份可复核文件的每一步走通。后续策略族沿用同一研究协议。[产品定位](../requirements/product-positioning.md) · [产品行为](../requirements/product-design-v0_0_1.md)

## 3. 用户如何控制一次研究

同一研究在桌面有一条时间线。举例，用户说“想看看美股最近跌得多的股票之后能不能反弹，最多让机器跑半小时”。系统保留原话，复述可执行的日频均值回归，说明股票池、进出规则及成本。它只追问最影响研究的问题。用户说“只看 A 股，其他先给建议”，摘要随之换市场并撤销不再适用的选择。主动建议的时间、方法或覆盖要求保持“待采纳”。五项设定为经济原理、市场与资产、最长有效时间、第一轮方法及版本、最低覆盖。确认卡还展示实际族与数据授权。用户明确确认后冻结 V1。

运行中用户问“为什么又试了一轮”，系统读取上一轮失败项、候选编号和本轮累计尝试数，返回可点回去的证据。若用户说“回撤过不了就放宽一点”，系统生成草案，列旧值、新值、影响和确认前已经存在的 EvidenceRef。澄清具体值并获确认才开新版。若用户说“只在同行业内比较，固定第三天卖出”而执行器不能实现，系统逐项标出差异，保持待答。预算耗尽返回研究记录和下一步可选动作。用户可单独重验某轮，合格时取得带规则、冻结定义和出处的策略包。[确认和版本](../requirements/product-design-v0_0_1.md#34-经济逻辑确认) · [策略族准入](../requirements/strategy-families-v1.md)

## 4. 运行时与数据契约

```text
桌面消息、按钮、重发 ─→ 本机命令服务 ─→ 加载研究与选定版本
                               │
              只读问题 ←─ 证据视图      草稿/变更 → 候选提议
                               │                      ↓
                               └── SQLite 事务 ← 领域校验/人工确认
                                        │
                                唯一 ResearchLoop
                   受权取材 → 冻结输入 → 构造候选 → 模拟与检验
                               ↑                  ↓
                         族内下一候选 ←── 审阅、预算、对照
                                                  ↓
                                      等待确认 / 结束 / 导出
```

**解释和执行。** 扩展 `send_dialogue` 为请求信封。现有 Tauri + loopback bearer /commands 继续校验顶层 schema。新桌面传 `command_id`（稳定 UUID）、`research_id`、`expected_revision`、`message`、可选的 `reply_to`（当前提议 ID）。`revision` 是会改变研究授权含义的单调版本，普通进度或只读问题不让确认卡失效。服务端返回当前研究版本、修订和命令回执，成功后仍可用 `fetch_view` 刷新。在途按钮和键入的肯定答复绑定同一提议。发送超时用原 ID 取回执，不能把旧“可以”套到新问题。

**模型的输入输出。** Python 定义可注入的 `propose(context) -> Proposal` 接口。每次输入包含角色、提示版本、消息原文或已准许的片段、能力列表、当前待答问题和必要的证据摘要。输出使用带判别字段的封闭 schema。下例是提议，不携带开跑许可。

```json
{"kind":"interpret_brief","fields":[
  {"field":"market","value":"US","quote":"美股"},
  {"field":"family","value":"mean_reversion","quote":"跌得多的股票之后能不能反弹"},
  {"field":"max_effective_hours","value":0.5,"quote":"最多让机器跑半小时"}
],"unresolved":[]}
```

本机归并已有规则的可靠解析与模型候选。每个字段有类型、单位、合法范围和消息来源。方法从本机可执行的 `MethodRef` 解析，代码交给原标的消歧逻辑。按分句登记“只、必须、排除、第几天”等硬限制，每项要有能力映射或待澄清记录。即使模型省略了限制也不得悄悄采纳缩减的论点。规则与模型冲突或多个族命中时由人选择。不支持的动量先硬阻断，不推荐均值回归。其他未实现族如要走既有披露路径，需明确同意改变执行方向。五项填齐与可开跑是两个判定。任何来源、经济逻辑和覆盖上的实质改动都重新计算相关许可。

**能力清单按副作用分级。** 以下是服务器能力名，模型只能给候选参数。每个参数由本机 schema 检查，每个引用按研究 ID、版本、轮次和快照权限解析。

| 用户动作或自动步骤 | 可以调用的能力 | 写入及权限边界 |
|---|---|---|
| 看进度、解释、比较、追溯材料 | `read_status / read_round / read_evidence` | 仅读冻结快照；没有数据就返回缺项。数值、币种、期间、单位由程序渲染 |
| 草稿补充、纠正和开跑 | `propose_brief / confirm_run` | 提议可替换，确认由人对同一修订触发。只有命令服务能创建 V1 |
| 运行中的一个步骤 | `gather / specify / simulate / verify / propose_next` | worker 只能调用当前族和版本登记的能力，输入、输出、耗时、重试均记账 |
| 用户的方向或验证修改 | `request_change / resolve_confirm` | 引擎分类为经济逻辑、数据血缘、覆盖或实现变更。经济/血缘改动与突破覆盖底线生成确认卡；同意后新版本 |
| 暂停、继续、重验、导出 | 既有 pause、resume、continue_iterate、reverify、export_artifact 命令 | 绑定用户点击/明确选择、目标轮次及资格快照；延长预算沿用现有确认规则。模型无权提高额度、写文件路径或选择导出类别 |

**如何选下一轮。** 按族登记执行方法、离散参数域、默认顺序、基准、数据需求和“可自动改变”的维度。均值回归以当前 `legacy_zscore_daily` 为起点。上一轮验证不过时，将失败维度、比较基线、已试候选与预算交给提议器。例如换手成本未通过时，可在已登记的较长回看期中提出候选，附已存在的失败记录及为何值得尝试。引擎核对 candidate ID、策略身份和输入版本，记录理由并把选中的参数送入实际的 `build` 和 `retry`。重复指纹且未出现新信息就换下一个候选。当前版本预算耗尽、没有合法候选或有效时间用完即诚实结束。审阅退回同样占用尝试账本。模型故障发生在选择了模型的运行中则进入暂停，用户恢复或主动换模型后留痕。V1 保持确定性 reviewer 裁决，语言模型可提供可追溯的审阅意见。[迭代边界](../requirements/v1-cut-line.md) · [模型角色](../requirements/settings-config-v1.md#3-大模型)

**方法库随研究积累。** 对话可建议新检验或复用已有检验，展示检验什么、阈值、需要的数据、失败如何解释。已有算子用登记过的 schema 组装；新增任意算法先作为待实现的方法建议，不能当作已通过的检查。每次定义变更产生不可变修订，必须有金标准输入和正反例，获准加入本研究时经新版本冻结方法集。其他研究显式选择该修订，旧包与重验仍使用原语义。[方法修订](../../engine/research/methods.py) · [冻结方法分发](../../engine/verifiers.py)

## 5. 状态、故障和证据

采用“研究聚合 + 小型追加日志”。已有六个研究状态继续决定产品行为。SQLite 中增设 `command_receipt(research_id,command_id,payload_hash,revision,result_ref)`、`research_event(research_id,seq,version,kind,refs)` 和 `step_run(research_id,version,round,attempt,step,input_hash,status,result_ref)`。第一、二组键分别唯一，步骤主键覆盖输入指纹。大文件只存于本机数据目录，日志存可解析引用。版本快照、尝试及结论是事实来源，模型摘要可删后重建。草稿逐字段区分原话、推断、模板及采纳者。

1. 命令先查幂等回执，同 ID 不同参数返回冲突。读取前置条件，把慢模型与联网操作放锁外。提交前重读研究及授权，检查期望修订，在短事务内写增量、事件、回执和新修订。过期提议保留为过期处理结果，不能修改较新版本。旧客户端继续用原入口，但不能确认未展示的新式提议。
2. worker 按研究串行领取一个步骤。文件先写临时文件、校验内容哈希、原子更名，再提交引用。掉电后按输入哈希复用完整结果；找不到或校验失败时重取准许重取的输入，无法复原的冻结输入让研究暂停。重复工具调用允许发生，已提交的研究动作不可重复。整轮提交包含 attempt、研究状态、版本/轮次、event、累计窗口 M，唯一步骤回执防止双计数。
3. 按研究分别计有效时间，以单调时钟累计工作片段。每个步骤都有执行截止、剩余额度、取消信号和有限重试。等待确认、已暂停和进程停机不计时。每 5 秒写累计片段，重启最多漏计一个心跳片段。首期一名计算 worker；另一个 RUNNING 研究在队列等待时不扣算力预算，列表和聊天仍可读取。
4. 每轮保存逻辑陈述、实际参数变化、候选总数、接受/失败次数、M、市场与数据版本、验证结果。跨研究/版本的 M 保持已有窗口口径，展示累计搜索规模。M 是披露，不作统计校正。搜索段达到冻结标准时，按第 8 节进入最终评价或以探索记录结束。研究结束时钱从何来、哪些证据不利、哪些条件未经检验都能定位原记录。回撤阈值等标准变更由人决定，保留旧失败版本，不把新阈值记作当初通过。
5. 原始材料与行情分开冻结。材料引用包含 `source_id, locator, published_at/precision, fetched_at, content_hash, rights`。区分发表日、实际可得日与抓取日。研究回答引用冻结的材料片段或结果字段；资料中的指令仅作为文本。新事实只影响新一版资料集合。行情窗口、标的池版本、成分时点、复权、基准、成本、缺失与交易制度逐项披露。当前名单重建历史有幸存者偏差，A 股涨跌停和 T+1 模拟以实际能力标示。
6. 重验由冻结轮次、规则修订和输入指纹定位，读取原实验所用的行情、材料和方法，产出关联原结果的另一条记录。当前有效结论的重验失败立即撤销本次交接资格，并标记受影响的旧包。导出实时检查已完成、冻结方法通过、无待确认、相关重验成立、PIT 已执行且通过及覆盖仍合格。新自适应模式还需要第 8 节规定的预注册最终行情检验通过。任一条件缺失则交研究记录并列失败项。结论不以模型的自评或单次收益替代验证。[产品交接规格](../requirements/product-design-v0_0_1.md#37-策略包导出交接)

## 6. 数据、模型和评估边界

|---|---|---|
| 行情与基准 | 用户选 Yahoo 或 AkShare 并按来源确认，版本固定适配器、代码、区间、基准与指纹。未来可加经许可的本地 CSV/provider | 数据不足在同源、同窗口内按已授权底线处理，跌破先停。接口代码的开源许可证不等于行情再分发权。[AKShare](https://github.com/akfamily/akshare/blob/f8dc2d6c6c3456f5cab037523459f9b5bd0ecbc7/README.md#data) · [项目数据规格](../requirements/settings-config-v1.md) |
| 论文和公告 | Crossref 查 DOI、题名、公开元数据/可用摘要，区分检索命中与实际用于论证。SEC 代码名录只作发行人映射；将来读取备案要保留 accession、受理时间和原文定位 | 无日期笔记可作线索，不能支撑需要时点的论断。得不到支持就报告证据不足。[Crossref REST](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) · [现有取材实现](../../engine/research/gather.py) |
| 模型与本机材料 | OpenAI 兼容接口可连本机或用户配置的服务，模型作为可替换解释器。确定性草稿和研究路径可在未配置 LLM 时运行 | 草稿理解加入现有设置 §3 是新增用途，先更新披露。按实际协议/主机/端口及用途版本核验授权，环境覆盖不能绕过。只发本轮必要原话、公开摘要/结果摘要；独立持仓清单、本地全文、行情、凭据和原始路径留本机。模型 POST 一律禁用自动跟随 3xx，包含同主机换端口和 HTTPS 降级。新 origin 必须单独授权并绑定凭据。[配置解析](../../engine/research/llm_config.py) |

模型请求每条有总时限、上下文大小和步数上限。首批建议草稿 12 秒、输入最多 4,000 字，研究阶段单次模型请求最多 60 秒并受剩余有效时间截断。草稿超时、坏 JSON 或无密钥时保留问题、使用规则继续。多个 host 不做隐式切换。跨轮只携带带来源的有限摘要，原始轨迹按研究存本机；遥测默认不含研究文本。

**可复核的成功标准。** 在同一份中英文留出对话上比较当前规则与新解释器，分别报告辨认/纠错、错误启动、额外追问及每轮延迟。正例必须到正确确认卡并产生对应第一轮；负例以停在正确位置为成功。验证用合成行情及固定材料作确定性演练，再用获准真实来源走美股和 A 股验收。模型选中一个候选后须能由记录独立重建相同的模拟输入和检查结果。另测无模型、时点不足、覆盖不足、大量尝试后偶然通过、重验推翻和不合格导出。验收衡量研究是否忠实完成，不要求策略盈利。[发布验收矩阵](../requirements/release-acceptance-v1.md)

## 7. 实现与验收的不变量

- **创建也可以重放。** 新桌面在发第一句前分配 research_id，创建命令同时带 command_id。事务对新 ID 执行插入并写回执，已有 ID 先检查创建回执。相同操作重开同一时间线，未知来源或负载冲突拒绝覆盖。旧式创建仍可返回服务端分配的 ID。
- **外发请求的唯一性与费用。** 慢调用之前用短事务占用 operation key，存 pending、预算预留、域修订及请求指纹。重复到达返回 pending 或旧回执。同一操作在原进程存活期间最多派发一次。中断后若无法确定提供方是否已执行，记 unknown 并保守计入成本。有可靠供应商幂等键才能自动按原键恢复；其余由用户决定是否承担另一次调用。提供方账单本身不受 SQLite 事务控制。纯本地可重算步骤可自动恢复。
- **试验身份取决于内容。** 候选指纹由规范化的实际参数、方向与交易成本、执行实现/方法修订、价格/基准与证据快照构成。排除运行 ID、retry 序号、创建时间和解释文本。两条不同措辞建议相同输入时只执行一个候选，技术失败留尝试记录，窗口 M 只按提交轮数增加。
- **资格按证据依赖判定。** 重验含版本、round_id、method_id/修订、输入哈希、结果和序号。当前结论的任何适用重验失败，包括 PIT，都会阻止导出；修复后须按已冻结规则重验并保留前次失败与其处置。旧版结果通过引用关系只标记依赖它的策略包，保留研究记录。新版本可清空活动重验列表，永久 journal 仍能查旧版本。历史包缺少可判定的引用时标为“关联待核”，禁止推断为最近一轮。
- **导出交接时点。** ZIP 先生成到用户不可见的私有暂存区。短事务用 expected_revision 再验完整资格，登记授权快照、文件哈希及命令回执。该提交是交接授权时点，随后才原子发布。未获授权时即使暂存文件哈希正确也不能发布；授权后翻案则按依赖标记历史结果。崩溃恢复须先找到授权记录，再验证内容。
- **同日历复现。** 在首轮计算前按冻结的对齐政策生成资产与基准的规范输入，同时保留原始日期。模拟、重验与包运行器消费同一规范表和缺失策略。以资产缺 D2、基准 D1/D2/D3 为 100/110/121 作回归；若按资产日历结算 D3，三处均用 21% 而非有处取 10%。新计量口径版本化，旧快照不能验证时明示缺口。
- **材料权利跟随输出。** 材料分 local_only、metadata_only、redistributable；未知按 local_only。策略包和研究记录各用字段白名单，区分使用过与仅浏览。私有材料对外只给不透露本机文件名的引用和指纹，公开元数据按许可带出，允许再分发的正文才可附上。对库和 ZIP 逐文件做路径及私密哨兵测试。本地详情仍可打开原件。
- **长跑时的读取成本。** 状态、修订、last_seq、最近一轮摘要用轻量列/投影更新。单 worker 查运行队列用状态索引，时间线按 (research_id,seq) 每页至多 50 条；查看列表、心跳和轮询不得反序列化所有研究或重写全历史。

## 8. 独立复核后的研究约束

**每一版继承完整的生效定义。** 本机打开 Vn 时先取父版冻结的有效定义，包含信号、家族、阈值、方法/修订、覆盖、成本、血缘、时间及候选空间，然后仅应用本次已批准的类型化差异。将 parent_version、父定义哈希、本版完整定义与差异共同落库。构建首轮、重验、确认卡与导出从同一冻结定义派生。导出使用下面的安全投影，包内禁止直接序列化本机含原话的整对象。V1 用 −25% 回撤下限，V2 收紧为 −10%，V3 仅改时长后，回撤 −18% 必须继续判失败。拒绝或撤回保留草案记录，父定义不变。旧记录若无法重建历史有效值，以原已执行 spec 作证据，不把猜测冻结为授权。

**分辨探索和最终检验。** 同一窗口内反复换参数属于探索。项目现有的五段检验、方法通过、M 和对话语料留出均不能证明策略有独立的行情验证。新自适应模式在确认前给出两种明示的交付条件。纯探索模式充分展示结果、试验次数和偏差，产出标有 `exploratory` 的研究记录。若希望研究有资格交策略包，预先锁定互不重合的探索段、末尾保留段、切分规则、暖机/持有期隔离、指标/阈值与费用。只向候选器和解释器提供探索段。胜者及其规范指纹冻结后，才允许对保留段做一次最终评价。数据不足时留在纯探索模式或由人调整授权，不能默默缩短底线。此项是对 vNext 自适应路径新增的标准，旧版按原资格读取，明确标出旧版检验范围。[已有版本边界](../requirements/v1-cut-line.md) · [Qlib 分段示例](https://github.com/microsoft/qlib/blob/54355232463878d2eebb91fe0ee5fa7fa1f5976c/examples/benchmarks/LightGBM/workflow_config_lightgbm_Alpha158.yaml)

**先隔离，再探测。** 开跑前先确定按交易日计算的探索边界与保留边界。草稿的 refresh_symbol_probe、确认时的窗口固定及标的覆盖/缩量、材料过滤、基准对齐和显示的失败原因一律只读探索段。未定切分前只展示静态目录，不做跨区报价可得性探测。候选器只获得带探索区间上界的只读 DataPort。保留段中首次上市的标的不得改变开封前的卡片、股票池、资格、试验顺序或耗时提示。开封后才检查其覆盖，不足按最终检验失败记录。

**股票池本身也有可得时间。** 注册用于筛选候选的成分表时记录来源、实际可得时点 actual_available_at、成员定义与内容指纹。独立最终评价要求选股时本机能出示探索截止日之前或当日已经可得的那一版。表的生成日只有在能证明它就是当时可用的名单时才作依据。晚于截止日或日期未知的名单，哪怕价格全部合格，也只能给探索级记录。动态成分策略还须按每个信号日选当时成员，否则披露为固定篮子研究。默认池不满足时，可选择有可信日期的既有冻结名单；无法取得就保留该限制。服务端资格门禁与 UI、导出说明使用同一结论。[池物化](../../engine/research/universe_pool.py) · [名单选择](../../engine/research/symbol_pool.py)

为此引擎在本机登记测试区间、输入血缘、选定候选、可见性与开封回执。按市场和**时间重叠**保守检查本机已研究、展示过的区间，不能通过复制研究、更换源或更名版本将同一段已见行情重新标为盲测。历史使用范围不明时标 unknown，不给独立验证资格。选择前封存段的值、哈希、汇总、材料与派生指标均不出现在选择器、对话和工具结果里。探索候选只按探索段输入指纹去重，保留段完整性哈希单独保存在受限的验证记录。冻结候选后先原子领取该窗口的评价权，再计算并按原键重放同一候选；进程失败不产生第二次挑选权。开封后想继续调参，原检验转为已见证据，新结论需另有未见区间。时间分段政策与可见性由引擎执行，只说明本机记录范围，不能证明用户从未在别处看过行情。独立评价失败或证据不明，API、桌面和导出一致只交研究记录。

**资料服务也有外发边界。** 模型设置的同意不授权向资料供应商发送自由论点。保留本机原话，用 `MaterialQuery(public_terms, provider_id, purpose, policy_revision)` 取代直接把 thesis 作为远端查询。public_terms 只能从公开家族词典、明确获准发往该来源的发行人标识等白名单生成。放行时记录准确的目的地与检索词，用户可在确认卡检视。其余内容仅在本机资料端使用；确需外发自拟片段时，逐来源显示原文、获准后才调用。模型关闭、端点失联或重启也不能解除该约束。URL、错误日志和导出均避免泄露原话。本机原始 thesis、改写前后的消息、原文引用和路径留在私有账本。两类包都从白名单构造：策略包的 spec.json 仅含可执行参数、规范化经济逻辑与不透露文本的引用 ID；研究记录只带获准展示的规范化说明和结果。规范化说明由枚举/结构字段按模板生成，不能把自由文字重新插入备注、manifest 或证据摘要。需要用户自备数据时按指纹核验。对包运行器和本机重放同一输入，参数、指标和门禁必须一致。[现有公开查询入口](../../engine/research/gather.py)
